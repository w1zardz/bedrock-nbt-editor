NBTエディター / playerdata

playerdataエディター — Minecraftプレイヤー.datファイル

Minecraft Bedrock EditionとJava Editionに対応し、一般的なものから小規模なものまで両方の全サーバーコアを扱えます: Vanilla、Paper、Spigot、Purpur、Folia、Fabric、Forge、NeoForge、Mohist、Sponge、Bedrock Dedicated Server、PocketMine-MP、Nukkit、PowerNukkitX、Cloudburst、Dragonfly、Endstone、LeviLaminaなど。全一覧。

Java Editionはプレイヤーごとにgzip圧縮ビッグエンディアンNBTを world/playerdata/<uuid>.dat へ保存します。インベントリ、エンダーチェスト、位置、ディメンション、体力、空腹度、XP、属性が含まれます。地形内に埋まった位置やクラッシュを起こすアイテム、統計を修正できます。サーバーを停止するか、対象プレイヤーをオフラインにしてください。

プレイヤーファイル内のタグ

タグ型内容
PosDouble のリストX、Y、Z。壁の中や岩盤下にいるプレイヤーの修正に使います。
RotationFloat のリストヨーとピッチ。
DimensionString / Intログイン時に入るディメンション。
InventoryCompound のリストスタックごとの項目: id、Count、Slot、components または tag。
EnderItemsCompound のリスト同じ形式のエンダーチェスト内容。
Health, foodLevel, XpLevel, XpTotalFloat / Int体力、空腹度、経験値。
playerGameTypeIntプレイヤー単位のゲームモード。
abilitiesCompound飛行、無敵、歩行速度、飛行速度。
AttributesCompound のリスト最大体力、移動速度、その他の補正。
SpawnX/SpawnY/SpawnZ または respawnInt / Compoundバージョンに応じた個人リスポーン地点。
UUIDInt[4]現行バージョンで4つのintとして保存されるUUID。

1.20.5でアイテムスタックの形式が変わり、カスタムデータは単一の tag Compoundから個別の components へ移動しました。どちらも開けるため、使用中のバージョンが書く形式を編集してください。

一般的な修復

  • 地形内に埋まった、または落下し続ける。Pos を安全なX、Y、Zの3つのdoubleへ変更し、Motion に極端な値があれば消去します。
  • ログイン時にクライアントがクラッシュする。不正なアイテムが主な原因です。Inventory 全体ではなく該当項目だけを削除します。
  • ポータル不具合で誤ったディメンションにいる。Dimension を minecraft:overworld へ戻し、Pos も対応する座標へ変更します。
  • スペクテイターから戻れない。playerGameType をサバイバルなら0、クリエイティブなら1にします。
  • 削除済みプラグインの属性補正が残る。Attributes 内の不要な項目を削除します。

プレイヤーをオフラインにして編集する

サーバーはプレイヤー状態をメモリーに保持し、ログアウト時と自動保存時に書き出します。オンライン中の編集は必ず上書きされ、保存中の編集はファイルを切断する可能性があります。プレイヤーをオフラインにするかサーバーを停止し、コピーを編集して、再接続前に戻してください。ログイン成功まで元ファイルを残します。

Bedrockサーバーはこの配置を使いません。プレイヤーデータはワールドのLevelDB内で player_<uuid> などのキーに保存され、値はリトルエンディアンNBTです。抽出すれば Bedrock 生データ として開けます。

よくある質問

自分のプレイヤーファイルはどれですか？

ファイル名はUUIDです。Mojang APIの確認ツールでUUIDを調べるか、playerdata/ を更新日時で並べて最終ログイン時刻と照合してください。

playerdataを編集してアイテムを追加できますか？

自分のサーバーなら、Inventory Listへ id、Count、Slot を持つ項目を追加できます。他人のサーバーでは不正アクセスに当たり、稼働中のサーバーがファイルを書き直すため動作もしません。

編集内容が消えたのはなぜですか？

編集時にサーバーまたはプレイヤーがオンラインだったためです。次の保存ではメモリー内のプレイヤー状態が優先されます。

Bedrockでもplayerdataは同じですか？

いいえ。BedrockはプレイヤーをUUID別ファイルではなくワールドのLevelDB内に保存します。値を抽出すると、その中のリトルエンディアンNBTをここで開けます。
