Editor de .mcstructure para estructuras de Bedrock

Compatible con Minecraft Bedrock Edition y Java Edition, y con todos sus núcleos de servidor, conocidos o no: Vanilla, Paper, Spigot, Purpur, Folia, Fabric, Forge, NeoForge, Mohist, Sponge, Bedrock Dedicated Server, PocketMine-MP, Nukkit, PowerNukkitX, Cloudburst, Dragonfly, Endstone, LeviLamina y el resto. Lista completa.

Un archivo .mcstructure es NBT little-endian sin comprimir escrito por un bloque de estructura de Bedrock. Arrastra uno para consultar su tamaño, paleta, índices de bloques y datos de entidades, editar cualquier valor y descargarlo con la misma codificación. Resulta útil para corregir una estructura de un add-on o mapa sin volver a abrir el mundo.

Qué contiene un .mcstructure

EtiquetaTipoContenido
format_versionIntRevisión del formato de estructura; 1 en los archivos actuales
sizeLista de IntDimensiones X, Y y Z del volumen capturado
structure_world_originLista de IntLugar del mundo donde se capturó la estructura
structureCompoundContiene todos los datos siguientes
structure.block_indicesLista de Int[]Dos capas de índices de paleta, normalmente bloques y anegamiento; -1 significa "dejar lo que ya existe"
structure.entitiesLista de CompoundEntidades capturadas con la estructura
structure.palette.default.block_paletteLista de CompoundCada estado de bloque distinto: name, states, version
structure.palette.default.block_position_dataCompoundNBT de entidades de bloque identificado por el índice lineal de la posición

Los índices de block_indices recorren X, luego Z y después Y: el índice lineal (x * sizeZ + z) * sizeY + y apunta a la lista de la paleta. Este mapeo permite corregir un bloque concreto sin regenerar la estructura.

Cambios habituales

  • Sustituir un tipo de bloque en todas partes editando una entrada de block_palette; todas las posiciones con ese índice cambiarán.
  • Corregir un estado de bloque, por ejemplo un facing incorrecto o un waterlogged accidental en el compuesto states.
  • Eliminar entidades capturadas por accidente, quitando entradas de la lista entities.
  • Reparar datos de entidades de bloque, como inventarios de cofres, texto de letreros o ajustes de generadores, dentro de block_position_data.
  • Comprobar la versión de las entradas de la paleta si una actualización hace que la estructura se importe con bloques incorrectos.

Dónde están los archivos

Los bloques de estructura guardan en la carpeta structures/ del mundo archivos llamados <namespace>_<name>.mcstructure. Los paquetes de comportamiento también los incluyen bajo structures/, donde el juego los carga por espacio de nombres. Ambos usan el mismo formato.

El equivalente de Java Edition es un archivo de estructura .nbt big-endian comprimido con gzip, con otra disposición de etiquetas. La página del editor para Java explica esos archivos, que también se abren aquí.

Preguntas frecuentes

¿Puedo convertir un .mcstructure en una estructura .nbt de Java?

El editor puede recodificar los bytes como gzip big-endian, pero la estructura de etiquetas es distinta. Java usa palette/blocks con otras claves y nombres de bloques. El archivo recodificado se puede leer, pero no es una estructura Java válida.

¿Por qué mi .mcstructure no está comprimido?

Bedrock escribe las estructuras como NBT little-endian sin contenedor gzip. Es normal; el editor lo detecta como Bedrock sin procesar.

¿Qué significa un índice -1 en block_indices?

Marca una posición que la estructura no modifica, por lo que al colocarla se conserva el bloque existente en el mundo.

¿Puedo cambiar el tamaño de una estructura editando size?

No por sí solo: block_indices contiene una entrada por posición y su longitud debe coincidir exactamente con el volumen nuevo. Cambiar solo size produce un archivo que el juego rechaza.
