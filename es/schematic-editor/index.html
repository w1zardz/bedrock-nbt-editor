Two formats, one file extension family

FormatExtensionKey tags
Sponge Schematic v2 (WorldEdit 7).schemVersion, DataVersion, Width, Height, Length, Palette, BlockData, BlockEntities, Offset, Metadata
Sponge Schematic v3.schemSame data nested under a Schematic compound, with Blocks holding Palette and Data
MCEdit legacy.schematicWidth, Height, Length, Blocks, Data, Entities, TileEntities, Materials

BlockData in the Sponge formats is a byte array of varint palette indices, not one byte per block — long ids continue across several bytes. The legacy format instead stores raw numeric block ids in Blocks with a parallel Data array of metadata nibbles, which is why old schematics lose fidelity on modern versions.

What is worth editing by hand

  • Palette entries. Rewriting minecraft:oak_planks to minecraft:spruce_planks in Palette re-skins every matching block in the schematic at once.
  • Offset and origin. Offset decides where the paste lands relative to your position — the fastest fix for a build that always arrives three blocks off.
  • Block entities. Chest inventories, sign lines and spawner data live in BlockEntities and can be cleaned before sharing a build.
  • Metadata. Metadata carries the author and the WorldEdit origin; harmless to edit and often worth clearing before publishing.
  • DataVersion. Tells you which Minecraft version produced the schematic, which explains most "unknown block" errors on paste.

Loader compatibility

WorldEdit and FastAsyncWorldEdit read .schem from plugins/WorldEdit/schematics/; legacy .schematic files still load but are converted on the way in. Litematica uses its own .litematic container — also NBT, and it opens in this editor, though its layout differs from the Sponge one. Whatever the flavour, the editor reads it as NBT and writes it back gzip-compressed, so the loader sees the file it expects.

Frequently Asked Questions

Can I open a .schem without a server or WorldEdit?

Yes. A .schem is just gzip big-endian NBT; the editor opens it in the browser with nothing else installed.

Why does my schematic paste with wrong blocks?

Usually a version mismatch — check DataVersion and the palette. A schematic exported on a newer version can reference block states an older server does not know.

Can I change a schematic's size here?

Not by editing Width/Height/Length alone. BlockData is sized to the volume, so the dimensions and the data have to change together — that is a job for WorldEdit, not a tag editor.

Does it open .litematic files?

Yes, as NBT. Litematica's own tag layout is not the Sponge one, so what you see is its native structure rather than a schematic palette.
