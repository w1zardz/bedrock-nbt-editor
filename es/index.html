Todos los archivos NBT que genera Minecraft

NBT (Named Binary Tag) es un formato con varias codificaciones, y cada edición, lanzador y núcleo de servidor de Minecraft usa una combinación distinta. Este editor admite todas y elige la correcta a partir de los propios bytes, por lo que no necesitas saber qué variante usa un archivo antes de abrirlo.

Cómo editar un archivo NBT

  1. Obtén el archivo del servidor o dispositivo. Los servidores de Java lo guardan en world/, los de Bedrock en worlds/YourWorld/ y Android en games/com.mojang/minecraftWorlds/<id>/. Detén primero el servidor para que no escriba en el archivo mientras lo copias.
  2. Arrástralo al editor. La insignia sobre el árbol indica qué se detectó: edición, codificación, compresión y, en Bedrock, la versión de almacenamiento del encabezado.
  3. Edita. Toca un valor para cambiarlo en el mismo lugar. Usa la búsqueda para ir a una etiqueta por nombre o valor, + para agregar etiquetas a cualquier compuesto o lista y × para eliminarlas.
  4. Guarda y descarga. Los selectores de formato de salida y compresión usan de forma predeterminada los del archivo original, por lo que una edición normal conserva fielmente los bytes.
  5. Vuelve a colocarlo y reinicia. Conserva el original como respaldo hasta que el mundo se haya cargado una vez y funcione correctamente.

Qué distingue a este editor

Cinco codificaciones en una sola zona

Big-endian de Java, little-endian de Bedrock, NBT de red varint de Bedrock, NBT de red con raíz sin nombre de Java 1.20.2+ y level.dat de Bedrock con encabezado. Se detectan; no se adivinan.

gzip y zlib en el navegador

La descompresión y la recompresión usan la API nativa Compression Streams, por lo que un level.dat de Java se puede abrir y guardar como un archivo que el juego acepta sin cambios.

Longs reales de 64 bits

Los valores TAG_Long se conservan como BigInt. Las semillas de mundo y las mitades de UUID sobreviven a la edición sin dañarse por el redondeo de punto flotante, donde fallan muchas herramientas NBT para navegador.

Codificación correcta de cadenas

Java escribe UTF-8 modificado (CESU-8) y Bedrock usa UTF-8 estándar. El editor codifica según la edición, por lo que los emojis y los nombres de mundo con caracteres no latinos se conservan.

Preparado para archivos grandes

Los arreglos se guardan en arreglos tipados y el árbol se renderiza de forma diferida, 200 entradas a la vez. Un megabyte de NBT de chunks se abre sin bloquear la pestaña.

Búsqueda en todo el árbol

Busca cualquier etiqueta por nombre o valor en todo el archivo y ve directamente a ella con la ruta expandida.

Exportación a SNBT

Exporta todo el árbol como SNBT, la forma de texto que usan /data y los paquetes de datos, para comparar, compartir o pegar el contenido en un comando.

Conversión de formato

Lee un archivo de Bedrock y escribe gzip big-endian de Java, o al revés. Es útil para trabajar con protocolos, pruebas y herramientas.

Nada sale de tu dispositivo

El archivo se lee con FileReader, se analiza en JavaScript y se devuelve como un blob en memoria. No existe ningún endpoint de carga.

Software de servidor compatible: todo

El juego, no la implementación del servidor, escribe NBT. Por eso, cualquier núcleo que almacene un mundo de Minecraft usa una de las codificaciones que lee este editor. La lista siguiente es completa y no publicitaria: si un núcleo escribe un mundo, usa la estructura de Vanilla porque el cliente del otro extremo debe poder leerlo.

Bedrock Edition: NBT little-endian y encabezado de 8 bytes en level.dat

Bedrock Dedicated Server (BDS), PocketMine-MP (PM3, PM4, PM5), Nukkit, Nukkit-MOT, PowerNukkitX, Cloudburst Server, Dragonfly, Endstone, LeviLamina y BDSX, Allay, JukeboxMC, GoMint, Sculk, ElementZero, LiteLoaderBDS, además de los propios clientes MCPE y MCBE en Android, iOS, Windows, consolas y Switch. El mismo worlds/<World>/level.dat, el mismo encabezado y las mismas etiquetas; consulta el flujo de trabajo del servidor.

Java Edition: NBT big-endian y gzip

Vanilla, CraftBukkit, Spigot, Paper, Purpur, Pufferfish, Folia, Leaves, Gale, Petal, Airplane, Sponge (SpongeVanilla, SpongeForge), Fabric, Quilt, Forge, NeoForge, Mohist, Arclight, Magma, Ketting, Banner, Cardboard, Glowstone, Thermos, Uberbukkit y cualquier otro fork, servidor de modpack o versión antigua. Si escribe world/level.dat, este editor lo abre; consulta los detalles aquí.

Proxies y puentes

Geyser, WaterdogPE, Waterfall, Velocity y BungeeCord no almacenan mundos; transportan NBT por la red. Las capturas de esos sockets son NBT de red: varint little-endian del lado de Bedrock y big-endian con raíz sin nombre en Java 1.20.2+. Ambos se abren aquí directamente.

Cualquier opción que no aparezca en la lista

Forks personalizados, núcleos privados, proyectos educativos o un servidor que hayas escrito: si el archivo es NBT, el editor detecta cuál de las cinco codificaciones usa y lo abre. Nada depende del nombre del núcleo.

Usa el analizador desde tu propio código

La página expone su motor en window.NBT, así que puedes controlar desde la consola del navegador el mismo analizador que usa la interfaz o reutilizarlo en un userscript:

const bytes = new Uint8Array(await file.arrayBuffer());
const { root, format, compression, headerVersion } = await NBT.read(bytes);

root.value.find(t => t.name === "LevelName").value = "New World";

const out = await NBT.write(root, format, { compression, headerVersion });

Las etiquetas son objetos simples, { type, name, value, listType }; los arreglos son Int8Array, Int32Array y BigInt64Array; y los longs son BigInt. La referencia del formato NBT documenta todos los tipos de etiqueta y las diferencias entre codificaciones.

Preguntas frecuentes

¿Este editor NBT es gratuito?

Sí, y su código fuente está disponible bajo la licencia MIT. No hay planes de pago, registro ni cuota de carga porque no existe ningún componente de servidor: todo el editor consta de una página estática y dos archivos de recursos.

¿Funciona con Java Edition y Bedrock Edition?

Con ambas. Los archivos de Java Edition son big-endian y suelen estar comprimidos con gzip; los de Bedrock son little-endian y level.dat incluye un encabezado adicional de 8 bytes. El editor detecta la variante recibida y la conserva al guardar.

¿Mi archivo de mundo se sube a algún sitio?

No. El archivo se lee localmente con la API FileReader y la descarga se genera desde un blob en memoria. Una vez cargada la página, puedes desconectarte de la red y seguirá funcionando.

¿Puedo usarlo en Android o iOS?

Sí. El diseño prioriza dispositivos móviles, con áreas táctiles de 44 px y una barra de acciones fija. En Android puedes elegir un archivo de mundo directamente desde un administrador de archivos; en iOS debe estar primero en la app Archivos debido al aislamiento del sistema.

¿Cuál es la diferencia entre NBT y SNBT?

NBT es la codificación binaria que Minecraft almacena en disco. SNBT es su forma de texto, la sintaxis que se usa en comandos como /data merge. Este editor lee NBT binario y puede exportar SNBT, lo que facilita comparar dos archivos o pegar una estructura en un comando.

¿Qué herramientas reemplaza?

Editores NBT de escritorio como NBTExplorer, además de varias herramientas web específicas que solo admiten una edición. Consulta la comparación con NBTExplorer en línea para ver qué funciones se conservan y cuáles no.
