Due formati per la stessa famiglia di estensioni

FormatoEstensioneTag principali
Sponge Schematic v2 (WorldEdit 7).schemVersion, DataVersion, Width, Height, Length, Palette, BlockData, BlockEntities, Offset, Metadata
Sponge Schematic v3.schemGli stessi dati sono annidati in un compound Schematic, mentre Blocks contiene Palette e Data
MCEdit precedente.schematicWidth, Height, Length, Blocks, Data, Entities, TileEntities, Materials

Nei formati Sponge, BlockData è un array di byte con indici varint della palette, non un byte per blocco: gli id lunghi continuano su più byte. Il formato legacy memorizza invece gli id numerici non elaborati dei blocchi in Blocks, insieme a un array Data parallelo di nibble dei metadati; per questo i vecchi schematic perdono precisione nelle versioni moderne.

Modifiche manuali utili

  • Voci della palette. Sostituendo minecraft:oak_planks con minecraft:spruce_planks in Palette, tutti i blocchi corrispondenti nello schematic cambiano insieme.
  • Offset e origine. Offset determina dove viene incollata la struttura rispetto alla tua posizione: è la correzione più rapida per una costruzione che compare sempre spostata di tre blocchi.
  • Entità blocco. Inventari dei bauli, righe dei cartelli e dati degli spawner si trovano in BlockEntities e possono essere ripuliti prima di condividere una costruzione.
  • Metadati. Metadata contiene l'autore e l'origine di WorldEdit; può essere modificato senza problemi e spesso conviene svuotarlo prima della pubblicazione.
  • DataVersion. Indica la versione di Minecraft che ha prodotto lo schematic e spiega la maggior parte degli errori "blocco sconosciuto" durante l'incollaggio.

Compatibilità dei programmi di caricamento

WorldEdit e FastAsyncWorldEdit leggono i file .schem da plugins/WorldEdit/schematics/; i file .schematic legacy vengono ancora caricati, ma sono convertiti durante l'importazione. Litematica usa il proprio contenitore .litematic, anch'esso NBT, che si apre in questo editor anche se la sua struttura è diversa da quella di Sponge. In ogni caso, l'editor legge il file come NBT e lo riscrive compresso con gzip, nel formato previsto dal programma di caricamento.

Domande frequenti

Posso aprire un file .schem senza server o WorldEdit?

Sì. Un file .schem è semplicemente NBT big-endian compresso con gzip; l'editor lo apre nel browser senza installare altro.

Perché il mio schematic viene incollato con blocchi errati?

Di solito dipende da versioni non compatibili: controlla DataVersion e la palette. Uno schematic esportato da una versione più recente può fare riferimento a stati dei blocchi sconosciuti a un server meno recente.

Posso cambiare qui le dimensioni di uno schematic?

Non modificando solo Width/Height/Length. BlockData è dimensionato in base al volume, quindi dimensioni e dati devono cambiare insieme: questa operazione va eseguita con WorldEdit, non con un editor di tag.

Apre i file .litematic?

Sì, come NBT. La struttura dei tag di Litematica è diversa da quella di Sponge, quindi viene mostrata la struttura nativa anziché una palette schematic.
