Editor playerdata — file .dat dei giocatori Minecraft

Supporta Minecraft Bedrock Edition e Java Edition e ogni core server per entrambe, diffuso o meno: Vanilla, Paper, Spigot, Purpur, Folia, Fabric, Forge, NeoForge, Mohist, Sponge, Bedrock Dedicated Server, PocketMine-MP, Nukkit, PowerNukkitX, Cloudburst, Dragonfly, Endstone, LeviLamina e gli altri. Elenco completo.

Java Edition scrive un file NBT big-endian gzip per ogni giocatore in world/playerdata/<uuid>.dat; contiene inventario, cassa di Ender, posizione, dimensione, salute, fame, XP e attributi. Trascinane uno qui sotto per liberare un giocatore bloccato nel terreno, rimuovere un oggetto che causa un arresto anomalo o azzerare le statistiche, con il server arrestato o almeno il giocatore offline.

La struttura delle pile di oggetti è cambiata nella versione 1.20.5: i dati personalizzati sono passati da un singolo compound tag a singoli components. Entrambe le strutture si aprono qui; modifica quella scritta dalla tua versione.

Riparazioni comuni

  • Giocatore bloccato nel terreno o in caduta continua. Imposta Pos su coordinate sicure — tre double nell'ordine X, Y, Z — e svuota Motion se contiene un valore molto grande.
  • Il client si arresta durante l'accesso. In genere la causa è un oggetto non valido. Rimuovi la voce problematica da Inventory invece di cancellare l'intera lista.
  • Dimensione errata dopo un problema con un portale. Reimposta Dimension su minecraft:overworld e assegna a Pos coordinate compatibili.
  • Bloccato in modalità spettatore. Imposta playerGameType su 0 per sopravvivenza o su 1 per creativa.
  • Modificatori degli attributi lasciati da un plugin rimosso. Elimina le voci obsolete in Attributes.

Esegui la modifica con il giocatore offline

Il server conserva lo stato del giocatore in memoria e lo scrive al logout e durante il salvataggio automatico. Se modifichi il file mentre il giocatore è online, le modifiche verranno sovrascritte; una modifica durante il salvataggio può troncare il file. Porta il giocatore offline, oppure arresta il server, copia e modifica il file, quindi ripristinalo prima che si riconnetta. Conserva l'originale finché l'accesso non riesce.

I server Bedrock non usano questa struttura: i dati dei giocatori si trovano nel LevelDB del mondo sotto chiavi come player_<uuid>, i cui valori sono NBT little-endian. Estrai un valore per aprirlo qui come Bedrock senza intestazione.

Domande frequenti

Qual è il file del mio giocatore?

I file prendono il nome dall'UUID. Cerca l'UUID del giocatore con un visualizzatore dell'API Mojang oppure ordina playerdata/ per data di modifica e confrontala con l'ultimo accesso.

Posso assegnarmi oggetti modificando playerdata?

Sul tuo server sì: aggiungi una voce alla lista Inventory con id, Count e Slot. Sul server di un'altra persona sarebbe un'intrusione e comunque non funzionerebbe, perché il server in esecuzione riscrive il file.

Perché la mia modifica è scomparsa?

Il server o il giocatore era online durante la modifica. Al salvataggio successivo prevale lo stato del giocatore conservato in memoria.

playerdata è uguale in Bedrock?

No. Bedrock conserva i giocatori nel LevelDB del mondo invece che in file distinti per UUID. I dati NBT contenuti in quei valori sono little-endian e, una volta estratti, si aprono qui.
