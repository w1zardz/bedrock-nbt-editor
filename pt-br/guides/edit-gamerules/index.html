Editando Regras de Jogo em level.dat

Compatível com Minecraft Bedrock Edition e Java Edition — e com todos os softwares de servidor de ambas as edições, conhecidos ou não: Vanilla, Paper, Spigot, Purpur, Folia, Fabric, Forge, NeoForge, Mohist, Sponge, Bedrock Dedicated Server, PocketMine-MP, Nukkit, PowerNukkitX, Cloudburst, Dragonfly, Endstone, LeviLamina e outros. Lista completa.

As regras de jogo ficam em level.dat e podem ser alteradas sem carregar o mundo nem ativar cheats. Isso ajuda quando o mundo não inicia, cheats estão desativados ou uma cópia está sendo preparada. Java as mantém em um compound GameRules como strings; Bedrock mantém cada uma em uma tag Byte minúscula na raiz.

keepInventorydoDaylightCyclemobGriefingcommandBlockOutputrandomTickSpeed

Java: um compound GameRules de strings

Na Java Edition, Data → GameRules contém uma TAG_String por regra, com o nome exato usado por /gamerule e valor em texto: "true", "false" ou um número. Regras nunca definidas ficam ausentes e usam o padrão; adicionar a tag com nome correto e valor String equivale a executar o comando.

RegraValorEfeito
keepInventory"true"Manter itens ao morrer
doDaylightCycle"false"Congelar o horário do dia
doWeatherCycle"false"Congelar o clima
mobGriefing"false"Impedir creepers e endermen de alterar blocos
doMobSpawning"false"Impedir spawn natural de mobs
doFireTick"false"Impedir propagação do fogo

randomTickSpeed"3"Velocidade de crescimento e propagação do fogo

Maiúsculas e minúsculas importam. keepinventory em um arquivo Java não é a mesma tag que keepInventory e será ignorada.

Bedrock: tags Byte minúsculas individuais

O Bedrock não agrupa regras. Cada uma é uma TAG_Byte na raiz de level.dat, com nome minúsculo e valor 1 ou 0, por exemplo keepinventory, domobspawning, domobloot, dodaylightcycle, doweathercycle, mobgriefing, firedamage, falldamage, drowningdamage, pvp, showcoordinates, commandblockoutput, sendcommandfeedback, naturalregeneration, tntexplodes, respawnblocksexplode, showdeathmessages, doimmediaterespawn. Regras numéricas como randomtickspeed e functioncommandlimit são TAG_Int.

Para definir uma regra ausente, adicione a tag com o tipo correto: Byte para opção booleana e Int para número. Uma regra com tipo errado é ignorada ou impede o carregamento.

Quando editar o arquivo é mais adequado

  • Cheats estão desativados e você não quer ativá-los apenas para executar um comando.
  • O mundo não carrega; uma regra como doImmediateRespawn pode ser definida antes da primeira entrada.
  • Você está preparando um mundo modelo para copiar em vários servidores e quer incluir as regras.
  • Um plugin alterou uma regra e você quer verificar o valor realmente armazenado, não apenas o exibido por um comando.
  • Edições em massa. Definir várias regras em diversos mundos é mais rápido no arquivo do que no chat.

Pare o servidor primeiro, como em qualquer edição de level.dat; um mundo em execução regrava o arquivo no save e descarta a alteração.

Perguntas frequentes

Por que a regra é armazenada como string no Java?

O Java armazena todas as regras como strings, inclusive booleanos e números. Grave "true", não um Byte de 1.

Por que ela é Byte no Bedrock?

O Bedrock armazena opções booleanas como tags Byte na raiz e regras numéricas como Ints. Não existe compound GameRules.

Uma regra está totalmente ausente do arquivo.

Isso significa que ela usa o padrão. Adicione a tag com nome exato e tipo correto para aplicar seu valor.

As regras são copiadas com a pasta do mundo?

Sim. Elas ficam em level.dat; portanto, uma cópia herda as regras e o antigo nome do mundo.
