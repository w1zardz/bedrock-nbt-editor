playerdata 편집기 — Minecraft 플레이어 .dat 파일

Minecraft Bedrock Edition과 Java Edition을 지원합니다. Vanilla, Paper, Spigot, Purpur, Folia, Fabric, Forge, NeoForge, Mohist, Sponge, Bedrock Dedicated Server, PocketMine-MP, Nukkit, PowerNukkitX, Cloudburst, Dragonfly, Endstone, LeviLamina 등 유명하거나 잘 알려지지 않은 양쪽 에디션의 모든 서버 코어를 지원합니다. 전체 목록

Java Edition은 플레이어마다 world/playerdata/<uuid>.dat에 gzip 빅 엔디언 NBT 파일 하나를 기록합니다. 인벤토리, 엔더 상자, 위치, 차원, 체력, 허기, XP, 속성이 들어 있습니다. 아래에 파일을 놓아 지형에 갇힌 플레이어를 옮기거나 충돌을 일으키는 아이템을 제거하고 통계를 초기화하세요. 서버를 중지하거나 최소한 해당 플레이어를 오프라인으로 만든 상태에서 작업해야 합니다.

1.20.5에서 아이템 스택 구조가 바뀌었습니다. 사용자 지정 데이터가 하나의 tag compound에서 개별 components로 이동했습니다. 두 구조 모두 여기서 열리므로 사용 중인 버전이 기록한 쪽을 수정하세요.

자주 필요한 복구 작업

  • 플레이어가 지형에 갇혔거나 계속 추락합니다. Pos를 안전한 좌표로 설정하세요. X, Y, Z 순서의 double 세 개입니다. Motion 값이 지나치게 크면 지웁니다.
  • 로그인할 때 클라이언트가 종료됩니다. 보통 잘못된 아이템이 원인입니다. 전체 목록을 지우지 말고 Inventory에서 문제 항목만 제거하세요.
  • 포털 오류 뒤 잘못된 차원에 있습니다. Dimension을 minecraft:overworld로 되돌리고 Pos에 해당 차원의 좌표를 지정하세요.
  • 관전자 모드에서 벗어나지 못합니다. playerGameType을 서바이벌은 0, 크리에이티브는 1로 설정하세요.
  • 삭제된 플러그인의 속성 수정자가 남았습니다. Attributes에서 오래된 항목을 삭제하세요.

플레이어가 오프라인일 때 작업하세요

서버는 플레이어 상태를 메모리에 보관하고 로그아웃과 자동 저장 때 파일에 기록합니다. 해당 플레이어가 온라인일 때 편집하면 변경 사항이 반드시 덮어써지고, 저장 중에 편집하면 파일이 잘릴 수 있습니다. 플레이어를 오프라인으로 만들거나 서버를 중지한 뒤 파일을 복사해 편집하고, 다시 접속하기 전에 원래 위치에 넣으세요. 로그인이 정상적으로 될 때까지 원본을 보관하세요.

Bedrock 서버는 이 구조를 사용하지 않습니다. 플레이어 데이터는 월드 LevelDB에서 player_<uuid> 같은 키 아래에 있으며 값은 리틀 엔디언 NBT입니다. 값을 추출하면 여기서 Bedrock 원시 형식으로 열립니다.

자주 묻는 질문

어느 파일이 제 플레이어 파일인가요?

파일명은 UUID입니다. Mojang API 뷰어에서 플레이어 UUID를 찾거나 playerdata/를 수정 시간순으로 정렬해 마지막 로그인 시각과 맞춰 보세요.

playerdata를 편집해 아이템을 받을 수 있나요?

자신의 서버에서는 가능합니다. Inventory 목록에 id, Count, Slot이 있는 항목을 추가하세요. 다른 사람의 서버에서는 침입에 해당하며, 실행 중인 서버가 파일을 다시 기록하므로 작동하지도 않습니다.

수정 내용이 사라진 이유는 무엇인가요?

편집할 때 서버나 플레이어가 온라인이었기 때문입니다. 다음 저장 때 메모리의 플레이어 상태가 파일을 덮어씁니다.

Bedrock의 playerdata도 같은가요?

아닙니다. Bedrock은 UUID별 파일 대신 월드 LevelDB 안에 플레이어 데이터를 저장합니다. 해당 값 안의 NBT는 리틀 엔디언이며 추출한 뒤 여기서 열 수 있습니다.
