Minecraft 파일을 수정하지 않고 내부만 확인하고 싶나요? 아래에 .nbt, .dat, .mcstructure, .schem 또는 원시 NBT 덤프를 놓으세요. 유형과 값을 포함한 전체 태그 트리를 보고 이름이나 값으로 검색하며 문서 전체를 SNBT 텍스트로 내보낼 수 있습니다. 파일은 업로드되지 않으며 저장을 누르기 전에는 아무것도 기록하지 않습니다.

직접 만들지 않은 파일 읽기

NBT 파일을 여는 이유의 절반은 문제 진단입니다. 어떤 버전이 기록했는지, 월드가 왜 불러와지지 않는지, 다른 사람이 보낸 schematic 안에 실제로 무엇이 있는지 확인할 수 있습니다. 뷰어는 모든 태그의 정확한 유형을 보여주므로 값이 1인 TAG_Byte와 값이 1인 TAG_Int를 구분할 수 있습니다. Minecraft에서는 이 차이가 중요하지만 일반 텍스트 덤프는 대개 이를 잃습니다.

  • 모든 행의 유형 배지: Byte, Short, Int, Long, Float, Double, Byte[], String, List, Compound, Int[], Long[].
  • 정확한 전체 64비트 long: 시드와 UUID 절반 값을 반올림 없이 올바르게 표시합니다.
  • 검색: 전체 트리에서 태그 이름이나 값으로 찾고 결과로 바로 이동합니다.
  • 감지한 형식: 파일 표시줄에 에디션, 바이트 순서, 압축, Bedrock 저장소 버전을 표시합니다.
  • SNBT 내보내기: 문서 전체를 텍스트로 만들어 비교하거나 명령어에 붙여넣고 다른 도구로 전달할 수 있습니다.

NBT와 SNBT의 차이

SNBT는 NBT의 텍스트 형식으로, /data get이 출력하고 명령어가 받는 형식입니다. 접미사로 유형 정보를 유지합니다. 3b는 byte, 3s는 short, 3L은 long, 3.0f는 float, 3.0d는 double, [I;1,2,3]은 int 배열입니다. 내보내기 버튼은 이 형식을 정확히 생성하므로 바이너리 파일을 명령 블록에 붙여넣거나 git에 넣어 줄 단위로 비교할 수 있습니다.

JSON은 대체 형식이 될 수 없습니다. 숫자 유형이 하나뿐이고 byte 배열이 없어 Minecraft에서 중요한 구분이 조용히 사라집니다. 이 도구가 JSON 대신 SNBT로 내보내는 이유입니다.

여기서 열 수 있는 파일

페이로드가 단일 NBT 문서인 파일이면 모두 열 수 있습니다. Java와 Bedrock level.dat, playerdata, servers.dat, hotbar.nbt, idcounts.dat, raids.dat, scoreboard.dat, 지도 데이터, 구조물 .nbt, .schem 및 .schematic, .mcstructure, .litematic, 추출한 청크 페이로드, 패킷 덤프가 해당합니다. .mca 리전, .mcworld 압축 파일, LevelDB 폴더 같은 컨테이너에서는 먼저 문서 하나를 추출해야 합니다.

자주 묻는 질문

NBT 파일을 수정하지 않고 볼 수 있나요?

네. 저장 및 다운로드를 누를 때만 새 파일을 기록하며 가져온 원본 파일은 건드리지 않습니다.

NBT를 JSON으로 변환할 수 있나요?

태그 유형을 보존하는 SNBT로 내보냅니다. JSON은 byte, short, int, long, float를 하나의 숫자 유형으로 합치고 byte 배열도 잃으므로 Minecraft 데이터를 왕복 변환하기에 적합하지 않습니다.

예상과 다른 에디션의 파일로 표시되는 이유는 무엇인가요?

확장자가 아니라 바이트에서 형식을 감지하기 때문입니다. Bedrock 파일이라고 생각했는데 Java로 표시된다면 보통 다른 에디션의 파일이거나 우연히 분석 가능한 조각입니다. 후행 바이트 경고가 나오면 보고된 오프셋을 확인하세요.

어느 정도 크기의 파일까지 열 수 있나요?

수 메가바이트 문서도 처리할 수 있습니다. 배열은 형식화 배열로 유지하고 트리를 지연 렌더링하므로 펼친 행만 페이지에 만들어집니다.
