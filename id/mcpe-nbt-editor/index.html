Header 8 byte dan alasan pentingnya

level.dat Bedrock bukan NBT mentah. Empat byte pertama adalah versi penyimpanan little-endian (nilai yang umum adalah 8 dan 10), empat byte berikutnya adalah panjang payload NBT dalam byte, lalu tag tanpa kompresi. Jika payload diedit tanpa memperbaiki panjang tersebut, permainan akan menolak file. Hal ini terjadi ketika penyimpanan Bedrock dibuka dengan alat NBT khusus Java.

OffsetUkuranKolom

Editor menampilkan versi penyimpanan pada bilah file, mempertahankannya, dan menulis ulang panjang secara otomatis setiap kali Anda menyimpan.

Tag Bedrock yang perlu diketahui

Bedrock menyimpan pengaturannya secara datar di root level.dat, bukan menempatkannya di bawah compound Data seperti Java. Aturan permainan juga disimpan sebagai tag individual, bukan sebagai anak GameRules.

TagTipeArti
LevelNameStringNama dunia yang ditampilkan dalam daftar dunia dan output server
GameTypeInt0 bertahan hidup, 1 kreatif, 2 petualangan
DifficultyInt0 damai … 3 sulit
commandsEnabledByteCheat aktif atau nonaktif
SpawnX, SpawnY, SpawnZIntSpawn dunia
RandomSeedLongSeed dunia, nilai 64-bit sebenarnya
lastOpenedWithVersionList berisi IntBuild klien atau server yang terakhir menulis dunia
StorageVersionIntRevisi penyimpanan dunia, sama dengan header
experimentsCompoundOpsi eksperimental yang diaktifkan untuk dunia
keepinventory, domobspawning, …ByteAturan permainan, masing-masing satu tag huruf kecil

Menemukan file pada setiap platform

  • Android: Android/data/com.mojang.minecraftpe/files/games/com.mojang/minecraftWorlds/<id>/level.dat. Versi Android yang lebih baru membatasi folder ini — gunakan ekspor dunia dalam permainan atau pengelola file dengan akses yang sesuai.
  • iOS: ekspor dunia ke .mcworld dari permainan, buka di aplikasi Files, lalu ekstrak di sana — level.dat berada di root arsip.
  • Windows: %LOCALAPPDATA%\Packages\Microsoft.MinecraftUWP_8wekyb3d8bbwe\LocalState\games\com.mojang\minecraftWorlds\<id>\level.dat.
  • Bedrock Dedicated Server: worlds/<World>/level.dat.
  • PocketMine-MP, Nukkit, PowerNukkitX: worlds/<World>/level.dat — lihat panduan sisi server.

Nama folder dunia adalah id acak, bukan nama dunia. Urutkan menurut waktu modifikasi, atau buka beberapa file level.dat di sini dan baca LevelName untuk menemukan file yang benar.

Selain level.dat

Bedrock menyimpan chunk, entitas, dan block entity dalam database LevelDB di folder db/, dengan NBT little-endian sebagai nilai untuk banyak key. Ekstrak sebuah nilai dan buka di sini sebagai Bedrock mentah — tanpa header dan tanpa kompresi. File struktur menggunakan pengodean yang sama: lihat editor .mcstructure. Data tangkapan protokol menggunakan varian varint yang dideteksi editor sebagai Jaringan Bedrock.

Pertanyaan yang sering diajukan

Mengapa level.dat Bedrock tidak dapat dibuka di NBTExplorer?

NBTExplorer mengharapkan tata letak big-endian Java dan tidak mengenali header Bedrock 8 byte. Editor ini menangani keduanya dan menulis ulang panjang pada header saat menyimpan.

Bisakah saya mengedit dunia MCPE di ponsel?

Bisa. Buka halaman ini di browser ponsel, pilih file dari pengelola file, lalu edit dan simpan. File hasil unduhan berada di folder Downloads; salin kembali untuk menggantikan file asli.

Apa perbedaan versi penyimpanan 8 dan 10?

Keduanya menandai revisi format penyimpanan dunia Bedrock; klien saat ini menulis versi 10. Editor mempertahankan nilai asli file dan tidak memaksakan versi tertentu karena mengubahnya tidak memigrasikan data dunia.

Apakah editor ini dapat membuka file .mcworld?

Tidak secara langsung — .mcworld adalah arsip zip. Ekstrak arsip, edit level.dat di sini, masukkan kembali ke arsip, lalu ubah kembali namanya menjadi .mcworld.

Apakah aturan permainan Bedrock didukung?

Ya. Bedrock menyimpan setiap aturan sebagai tag byte huruf kecil tersendiri di root — keepinventory, domobspawning, showcoordinates, dan seterusnya. Atur byte ke 1 atau 0. Panduan aturan permainan memuat daftarnya.
