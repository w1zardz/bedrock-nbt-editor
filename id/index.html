Semua file NBT yang ditulis Minecraft

NBT (Named Binary Tag) adalah satu format dengan beberapa pengodean. Setiap edisi Minecraft, launcher, dan core server memakai kombinasi yang berbeda. Editor ini mendukung semuanya dan menentukan format yang tepat langsung dari byte file, jadi Anda tidak perlu mengetahui variannya sebelum membuka file.

Cara mengedit file NBT

  1. Salin file dari server atau perangkat. Server Java menyimpannya di world/, server Bedrock di worlds/YourWorld/, dan Android di games/com.mojang/minecraftWorlds/<id>/. Hentikan server terlebih dahulu agar file tidak sedang ditulis saat disalin.
  2. Letakkan file di editor. Lencana di atas struktur pohon menunjukkan edisi, pengodean, kompresi, dan untuk Bedrock, versi penyimpanan dari header yang terdeteksi.
  3. Ubah nilai. Ketuk nilai untuk mengubahnya langsung. Gunakan pencarian untuk menuju tag berdasarkan nama atau nilai, + untuk menambahkan tag ke compound atau list, × untuk menghapusnya.
  4. Simpan & Unduh. Format keluaran dan pilihan kompresi mengikuti format file asal secara bawaan, sehingga pengeditan biasa mempertahankan format biner file aslinya.
  5. Kembalikan file lalu mulai ulang. Simpan file asli sebagai cadangan sampai dunia berhasil dimuat dan tampil dengan benar.

Hal yang membuat editor ini berbeda

Lima pengodean, satu area file

Java big-endian, Bedrock little-endian, NBT jaringan varint Bedrock, NBT jaringan dengan root tanpa nama dari Java 1.20.2+, dan level.dat Bedrock dengan header. Semuanya dideteksi, bukan ditebak.

gzip dan zlib di browser

Dekompresi dan kompresi ulang memakai Compression Streams API bawaan, sehingga level.dat Java dapat disimpan kembali sebagai file yang diterima gim tanpa perubahan format.

Bilangan bulat 64-bit yang utuh

TAG_Long disimpan sebagai BigInt. Seed dunia dan kedua bagian UUID tetap utuh setelah diedit, tanpa rusak akibat pembulatan floating-point yang sering bermasalah pada alat NBT berbasis browser.

Pengodean string yang benar

Java menulis UTF-8 termodifikasi (CESU-8), sedangkan Bedrock memakai UTF-8 standar. Editor menerapkan pengodean sesuai edisi agar emoji dan nama dunia non-Latin tetap utuh.

Dirancang untuk file besar

Array disimpan dalam typed array dan pohon dirender bertahap, 200 entri sekaligus. NBT chunk berukuran megabyte dapat dibuka tanpa membuat tab macet.

Pencarian di seluruh pohon

Temukan tag berdasarkan nama atau nilai di seluruh file, lalu langsung buka tag tersebut dengan path yang telah dibentangkan.

Ekspor SNBT

Ekspor seluruh pohon sebagai SNBT, yaitu bentuk teks yang digunakan oleh /data dan datapack, untuk dibandingkan, dibagikan, atau ditempelkan ke perintah.

Konversi format

Baca file Bedrock lalu tulis sebagai Java big-endian gzip, atau sebaliknya. Berguna untuk protokol, pengujian, dan pengembangan alat.

Tidak ada data yang keluar dari perangkat

File dibaca dengan FileReader, diurai dalam JavaScript, lalu dikembalikan sebagai blob di memori. Tidak ada endpoint unggahan.

Perangkat lunak server yang didukung

NBT ditulis oleh gim, bukan implementasi server. Karena itu, setiap core yang menyimpan dunia Minecraft memakai salah satu pengodean yang dapat dibaca editor ini. Daftar di bawah bersifat teknis: core yang menulis dunia mengikuti struktur Vanilla agar klien dapat membacanya.

Bedrock Edition — NBT little-endian, level.dat header 8 byte

Bedrock Dedicated Server (BDS), PocketMine-MP (PM3, PM4, PM5), Nukkit, Nukkit-MOT, PowerNukkitX, Cloudburst Server, Dragonfly, Endstone, LeviLamina dan BDSX, Allay, JukeboxMC, GoMint, Sculk, ElementZero, LiteLoaderBDS, serta klien MCPE dan MCBE di Android, iOS, Windows, konsol, dan Switch. Semuanya memakai worlds/<World>/level.dat, header yang sama, dan tag yang sama—lihat alur kerja sisi server.

Java Edition — NBT big-endian, gzip

Vanilla, CraftBukkit, Spigot, Paper, Purpur, Pufferfish, Folia, Leaves, Gale, Petal, Airplane, Sponge (SpongeVanilla, SpongeForge), Fabric, Quilt, Forge, NeoForge, Mohist, Arclight, Magma, Ketting, Banner, Cardboard, Glowstone, Thermos, Uberbukkit dan semua fork, server modpack, atau build lama lainnya. Jika menulis world/level.dat, editor ini dapat membukanya— lihat detail.

Proxy dan bridge

Geyser, WaterdogPE, Waterfall, Velocity dan BungeeCord tidak menyimpan dunia; perangkat lunak tersebut mengirim NBT melalui jaringan. Data tangkapan socket berupa NBT jaringan—varint little-endian di sisi Bedrock dan big-endian dengan root tanpa nama pada Java 1.20.2+—dan keduanya dapat langsung dibuka di sini.

Perangkat lunak yang tidak tercantum

Fork khusus, core privat, proyek pembelajaran, atau server buatan sendiri tetap didukung jika filenya berupa NBT. Editor mendeteksi salah satu dari lima pengodean dan membukanya; tidak ada fungsi yang bergantung pada nama core.

Gunakan parser dari kode Anda sendiri

Halaman ini menyediakan engine melalui window.NBT, sehingga parser yang dipakai UI dapat dijalankan dari konsol browser atau digunakan kembali dalam userscript:

const bytes = new Uint8Array(await file.arrayBuffer());
const { root, format, compression, headerVersion } = await NBT.read(bytes);

root.value.find(t => t.name === "LevelName").value = "New World";

const out = await NBT.write(root, format, { compression, headerVersion });

Tag berupa objek biasa— { type, name, value, listType } —array berupa Int8Array, Int32Array dan BigInt64Array, sedangkan long berupa BigInt. Referensi format NBT lengkap menjelaskan setiap jenis tag dan perbedaan antar-pengodean.

Pertanyaan yang sering diajukan

Apakah pengedit NBT ini gratis?

Ya. Editor ini bersumber terbuka dengan lisensi MIT. Tidak ada paket berbayar, pendaftaran, atau kuota unggahan karena tidak ada komponen server; editor hanya terdiri dari satu halaman statis dan dua file aset.

Apakah editor ini mendukung Java Edition dan Bedrock Edition?

Keduanya. File Java Edition memakai big-endian dan biasanya dikompresi dengan gzip; file Bedrock memakai little-endian, sedangkan level.dat memiliki header tambahan 8 byte. Editor mendeteksi varian file dan menulis kembali varian yang sama saat disimpan.

Apakah file dunia saya diunggah?

Tidak. File dibaca secara lokal dengan FileReader API dan hasil unduhan dibuat dari blob di memori. Setelah halaman dimuat, editor tetap berfungsi meski koneksi jaringan diputus.

Dapatkah editor ini digunakan di Android atau iOS?

Ya. Tata letaknya dirancang untuk perangkat seluler dengan target sentuh 44 px dan bilah tindakan yang selalu berada di posisi yang sama. Di Android, file dunia dapat dipilih dari pengelola file. Di iOS, file harus lebih dahulu disimpan di aplikasi Files karena sandboxing.

Apa perbedaan antara NBT dan SNBT?

NBT adalah format pengodean biner yang digunakan Minecraft untuk menyimpan data di disk. SNBT adalah bentuk teksnya, yaitu sintaks yang Anda ketikkan dalam perintah seperti /data merge. Editor ini membaca NBT biner dan mengekspor SNBT, sehingga Anda dapat membandingkan dua file atau menyisipkan struktur ke dalam perintah.

Alat apa yang dapat digantikan?

Editor NBT desktop seperti NBTExplorer serta berbagai alat web khusus yang hanya mendukung satu edisi. Lihat perbandingan NBTExplorer di browser untuk mengetahui fungsi yang tersedia dan yang tidak.
