Każdy plik NBT zapisywany przez Minecraft

NBT (Named Binary Tag) to jeden format mający kilka sposobów kodowania, a każda edycja Minecraft, program uruchamiający i rdzeń serwera używa ich innego połączenia. Ten edytor obsługuje wszystkie warianty i rozpoznaje właściwy na podstawie samych bajtów, więc przed otwarciem pliku nie musisz wiedzieć, w jakim wariancie został zapisany.

Jak edytować plik NBT

  1. Pobierz plik z serwera lub urządzenia. Serwery Java przechowują go w world/, serwery Bedrock w worlds/YourWorld/, a Android w games/com.mojang/minecraftWorlds/<id>/. Najpierw zatrzymaj serwer, aby podczas kopiowania plik nie był zapisywany.
  2. Przeciągnij go do edytora. Etykieta nad drzewem pokaże wykrytą edycję, kodowanie, kompresję, a w przypadku Bedrock także wersję magazynu z nagłówka.
  3. Edytuj. Dotknij wartości, aby zmienić ją w miejscu. Wyszukiwarka pozwala przejść do tagu według nazwy lub wartości, + dodaje tagi do dowolnego tagu złożonego lub listy, a × je usuwa.
  4. Zapisz i pobierz. Selektory formatu wyjściowego i kompresji są domyślnie ustawione zgodnie z plikiem źródłowym, dzięki czemu zwykła edycja zachowuje jego format bajt po bajcie.
  5. Wgraj plik z powrotem i uruchom ponownie. Zachowaj oryginał jako kopię zapasową, dopóki świat nie wczyta się poprawnie przynajmniej raz.

Co wyróżnia ten edytor

Pięć kodowań, jedno pole

Wielkobajtowe NBT Java, małobajtowe NBT Bedrock, sieciowe NBT Bedrock z varint, sieciowe NBT bez nazwanego korzenia z Java 1.20.2+ oraz level.dat Bedrock z nagłówkiem. Format jest wykrywany, a nie zgadywany.

gzip i zlib w przeglądarce

Dekompresja i ponowna kompresja korzystają z natywnego Compression Streams API, dlatego plik Java level.dat po edycji nadal jest akceptowany przez grę bez dodatkowych zmian.

Prawdziwe 64-bitowe liczby całkowite

Wartości TAG_Long są przechowywane jako BigInt. Ziarna światów i połowy UUID pozostają nienaruszone podczas edycji, zamiast ulegać zniekształceniu przez zaokrąglanie zmiennoprzecinkowe, z którym nie radzi sobie wiele przeglądarkowych narzędzi NBT.

Poprawne kodowanie tekstu

Java zapisuje zmodyfikowany UTF-8 (CESU-8), a Bedrock standardowy UTF-8. Edytor koduje dane odpowiednio do edycji, więc emoji i niełacińskie nazwy światów pozostają nienaruszone.

Przystosowany do dużych plików

Tablice są przechowywane w tablicach typowanych, a drzewo renderuje się stopniowo po 200 wpisów. Megabajt danych NBT chunka otwiera się bez zawieszania karty.

Wyszukiwanie w całym drzewie

Znajdź dowolny tag według nazwy lub wartości w całym pliku i przejdź bezpośrednio do niego z rozwiniętą ścieżką.

Eksport SNBT

Wyeksportuj całe drzewo jako SNBT — format tekstowy używany przez /data i datapacki — aby porównywać, udostępniać lub wklejać dane do polecenia.

Konwersja formatów

Odczytaj plik Bedrock i zapisz go jako wielkobajtowy plik Java skompresowany gzipem albo wykonaj konwersję odwrotną. Przydaje się to podczas pracy z protokołami, testami i narzędziami.

Nic nie opuszcza Twojego urządzenia

Plik jest odczytywany przez FileReader, analizowany w JavaScript i zwracany jako obiekt w pamięci. Nie istnieje żaden punkt końcowy do wysyłania plików.

Obsługiwane oprogramowanie serwerowe — bez wyjątków

NBT jest zapisywany przez grę, a nie przez implementację serwera. Każdy rdzeń przechowujący świat Minecraft zapisuje go więc w jednym z kodowań obsługiwanych przez ten edytor. Poniższa lista jest kompletna i nie służy marketingowi: rdzeń zapisujący świat musi zachować strukturę Vanilla, ponieważ klient po drugiej stronie musi umieć ją odczytać.

Vanilla, CraftBukkit, Spigot, Paper, Purpur, Pufferfish, Folia, Leaves, Gale, Petal, Airplane, Sponge (SpongeVanilla, SpongeForge), Fabric, Quilt, Forge, NeoForge, Mohist, Arclight, Magma, Ketting, Banner, Cardboard, Glowstone, Thermos, Uberbukkit oraz każdy inny fork, serwer modpacka czy stara wersja. Jeśli zapisuje world/level.dat, ten edytor go otworzy — szczegóły tutaj.

Serwery proxy i mosty

Geyser, WaterdogPE, Waterfall, Velocity i BungeeCord nie przechowują światów, lecz przesyłają NBT przez sieć. Dane przechwycone z ich gniazd to sieciowe NBT — małobajtowe z varint po stronie Bedrock i wielkobajtowe bez nazwanego korzenia w Java 1.20.2+ — a oba warianty można tutaj otworzyć bezpośrednio.

Wszystko, czego nie ma na tej liście

Niestandardowe forki, prywatne rdzenie, projekty edukacyjne czy samodzielnie napisany serwer: jeśli plik jest w formacie NBT, edytor wykryje jedno z pięciu kodowań i go otworzy. Działanie edytora nie zależy od nazwy rdzenia.

Użyj parsera we własnym kodzie

Strona udostępnia swój silnik jako window.NBT, więc parser obsługujący interfejs można wywołać z konsoli przeglądarki lub ponownie wykorzystać w skrypcie użytkownika:

const bytes = new Uint8Array(await file.arrayBuffer());
const { root, format, compression, headerVersion } = await NBT.read(bytes);

root.value.find(t => t.name === "LevelName").value = "New World";

const out = await NBT.write(root, format, { compression, headerVersion });

Tagi są zwykłymi obiektami — { type, name, value, listType } — tablice mają typy Int8Array, Int32Array i BigInt64Array, a liczby typu long są reprezentowane jako BigInt. Pełna dokumentacja formatu NBT opisuje każdy typ tagu i różnice między sposobami kodowania.

Najczęściej zadawane pytania

Czy ten edytor NBT jest darmowy?

Tak, a jego kod źródłowy jest dostępny na licencji MIT. Nie ma płatnego planu, rejestracji ani limitu wysyłania plików, ponieważ nie istnieje żaden komponent serwerowy — cały edytor to jedna statyczna strona i dwa pliki zasobów.

Czy edytor działa z Java Edition i Bedrock Edition?

Tak, z obiema edycjami. Pliki Java Edition są wielkobajtowe i zwykle skompresowane gzipem, natomiast pliki Bedrock są małobajtowe, a level.dat zawiera dodatkowy 8-bajtowy nagłówek. Edytor wykrywa otrzymany wariant i zapisuje plik w tej samej postaci.

Czy plik mojego świata jest gdzieś wysyłany?

Nie. Plik jest odczytywany lokalnie przez FileReader API, a pobierany wynik powstaje z obiektu przechowywanego w pamięci. Po załadowaniu strony możesz odłączyć urządzenie od sieci, a edytor nadal będzie działał.

Czy mogę używać edytora na Androidzie lub iOS?

Tak. Interfejs zaprojektowano przede wszystkim z myślą o urządzeniach mobilnych: elementy dotykowe mają 44 px, a pasek działań jest nieruchomy. Na Androidzie możesz wybrać plik świata bezpośrednio w menedżerze plików. Ze względu na izolację aplikacji w iOS plik musi najpierw trafić do aplikacji Pliki.

Czym różnią się NBT i SNBT?

NBT to format binarny, w którym Minecraft zapisuje dane na dysku. SNBT jest jego postacią tekstową, używaną w poleceniach takich jak /data merge. Ten edytor odczytuje binarne NBT i potrafi eksportować SNBT, co ułatwia porównywanie dwóch plików lub wklejanie struktury do polecenia.

Jakie narzędzia może zastąpić ten edytor?

Komputerowe edytory NBT, takie jak NBTExplorer, oraz różne jednofunkcyjne narzędzia internetowe obsługujące tylko jedną edycję. Zobacz porównanie z NBTExplorer online, aby sprawdzić, które funkcje są dostępne, a których brakuje.
