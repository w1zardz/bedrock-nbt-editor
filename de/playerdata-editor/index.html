NBT-Editor / playerdata

playerdata Editor – Minecraft-Spielerdateien .dat

Unterstützt Minecraft Bedrock Edition und Java Edition – einschließlich jedes bekannten oder seltenen Serverkerns: Vanilla, Paper, Spigot, Purpur, Folia, Fabric, Forge, NeoForge, Mohist, Sponge, Bedrock Dedicated Server, PocketMine-MP, Nukkit, PowerNukkitX, Cloudburst, Dragonfly, Endstone, LeviLamina und weitere. Vollständige Liste.

Die Java Edition schreibt für jeden Spieler eine gzip-komprimierte Big-Endian-NBT-Datei unter world/playerdata/<uuid>.dat. Sie enthält Inventar, Endertruhe, Position, Dimension, Gesundheit, Hunger, XP und Attribute. Ziehe eine Datei nach unten, um einen im Gelände feststeckenden Spieler zu versetzen, einen Absturz verursachenden Gegenstand zu löschen oder Werte zurückzusetzen. Der Server muss gestoppt oder zumindest der Spieler offline sein.

Die Struktur von Gegenstandsstapeln wurde in 1.20.5 geändert. Benutzerdefinierte Daten liegen seitdem nicht mehr in einem einzelnen Compound tag, sondern in einzelnen components. Beide Formen lassen sich hier öffnen; bearbeite die von deiner Version geschriebene Struktur.

Häufige Reparaturen

  • Spieler steckt im Gelände fest oder fällt endlos. Setze Pos auf sichere Koordinaten – drei Double-Werte in der Reihenfolge X, Y, Z – und leere Motion, falls dort ein sehr großer Wert steht.
  • Client stürzt beim Anmelden ab. Häufig ist ein fehlerhafter Gegenstand die Ursache. Entferne nur den betroffenen Eintrag aus Inventory, statt die gesamte Liste zu leeren.
  • Falsche Dimension nach einem Portalfehler. Setze Dimension auf minecraft:overworld zurück und trage passende Koordinaten in Pos ein.
  • Im Zuschauermodus festgesetzt. Setze playerGameType für Überleben auf 0 oder für Kreativ auf 1.
  • Attribut-Modifikatoren eines entfernten Plugins. Lösche die veralteten Einträge in Attributes.

Nur bei offline geschaltetem Spieler bearbeiten

Der Server hält den Spielerstatus im Arbeitsspeicher und schreibt ihn beim Abmelden und automatischen Speichern in die Datei. Wenn der Spieler online ist, werden deine Änderungen beim nächsten Speichern überschrieben. Eine Bearbeitung während des Speicherns kann die Datei abschneiden. Nimm den Spieler offline oder stoppe den Server, kopiere und bearbeite die Datei und lege sie vor der nächsten Anmeldung zurück. Bewahre das Original auf, bis die Anmeldung funktioniert.

Bedrock-Server verwenden diese Struktur nicht. Spielerdaten liegen in der LevelDB der Welt unter Schlüsseln wie player_<uuid>, deren Werte Little-Endian-NBT sind. Ein extrahierter Wert lässt sich hier als Bedrock-Rohdaten öffnen.

Häufig gestellte Fragen

Welche Datei gehört zu meinem Spieler?

Die Dateien sind nach UUID benannt. Ermittle die UUID des Spielers über eine Anzeige der Mojang API oder sortiere playerdata/ nach Änderungszeit und gleiche sie mit der letzten Anmeldung ab.

Kann ich mir durch Bearbeiten von playerdata Gegenstände geben?

Auf deinem eigenen Server ja. Füge der Liste Inventory einen Eintrag mit id, Count und Slot hinzu. Auf einem fremden Server wäre das ein unbefugter Eingriff und funktioniert zudem nicht, weil der laufende Server die Datei neu schreibt.

Warum ist meine Änderung verschwunden?

Der Server oder der Spieler war während der Bearbeitung online. Beim nächsten Speichern überschreibt der Status im Arbeitsspeicher die Datei.

Ist playerdata in Bedrock identisch?

Nein. Bedrock speichert Spieler in der LevelDB der Welt statt in einzelnen UUID-Dateien. Das NBT in diesen Werten ist Little-Endian und lässt sich nach dem Extrahieren hier öffnen.
