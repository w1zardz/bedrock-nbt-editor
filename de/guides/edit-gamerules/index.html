Spielregeln in level.dat bearbeiten

Unterstützt Minecraft Bedrock Edition und Java Edition – einschließlich jedes bekannten oder seltenen Serverkerns: Vanilla, Paper, Spigot, Purpur, Folia, Fabric, Forge, NeoForge, Mohist, Sponge, Bedrock Dedicated Server, PocketMine-MP, Nukkit, PowerNukkitX, Cloudburst, Dragonfly, Endstone, LeviLamina und weitere. Vollständige Liste.

Spielregeln werden in level.dat gespeichert. Du kannst sie daher ändern, ohne die Welt zu laden oder Cheats zu aktivieren. Das hilft, wenn eine Welt nicht startet, Cheats deaktiviert sind oder du eine kopierte Welt vor dem Beitritt der Spieler vorbereitest. Java speichert Regeln als Strings in einem Compound GameRules; Bedrock speichert jede Regel als eigenen kleingeschriebenen Byte-Tag im Root-Tag.

keepInventorydoDaylightCyclemobGriefingcommandBlockOutputrandomTickSpeed

Java: Strings in einem Compound GameRules

In der Java Edition enthält Data → GameRules pro Regel einen TAG_String. Der Schlüssel entspricht exakt dem von /gamerule verwendeten Namen, und der Wert wird als Text gespeichert: "true", "false" oder eine Zahl. Regeln, die in der Welt nie gesetzt wurden, fehlen und verwenden ihren Standardwert. Ein Tag mit dem korrekten Namen und einem String-Wert wirkt genauso wie der entsprechende Befehl.

RegelWertAuswirkung
keepInventory"true"Gegenstände beim Tod behalten
doDaylightCycle"false"Tageszeit anhalten
doWeatherCycle"false"Wetterwechsel anhalten
mobGriefing"false"Blockänderungen durch Creeper und Endermen verhindern
doMobSpawning"false"Natürliches Spawnen von Mobs verhindern
doFireTick"false"Ausbreitung von Feuer anhalten
commandBlockOutput"false"Chat-Ausgaben von Befehlsblöcken unterdrücken
randomTickSpeed"3"Geschwindigkeit von Pflanzenwachstum und Feuerausbreitung
playersSleepingPercentage"50"Anteil der Spieler, der zum Überspringen der Nacht schlafen muss
spawnRadius"10"Ausdehnung des Spawngebiets

Groß- und Kleinschreibung sind relevant. keepinventory ist in einer Java-Datei nicht derselbe Tag wie keepInventory und wird ignoriert.

Bedrock: einzelne kleingeschriebene Byte-Tags

Bedrock gruppiert Regeln nicht. Jede Regel ist ein TAG_Byte im Root-Tag von level.dat, kleingeschrieben und mit dem Wert 1 oder 0: keepinventory, domobspawning, domobloot, dodaylightcycle, doweathercycle, mobgriefing, firedamage, falldamage, drowningdamage, pvp, showcoordinates, commandblockoutput, sendcommandfeedback, naturalregeneration, tntexplodes, respawnblocksexplode, showdeathmessages, doimmediaterespawn. Numerische Regeln wie randomtickspeed und functioncommandlimit sind dagegen TAG_Int.

Wenn eine noch nicht vorhandene Regel gesetzt werden soll, muss der Tag mit dem richtigen Typ hinzugefügt werden: Byte für einen Schalter, Int für eine Zahl. Eine Regel mit falschem Typ wird ignoriert oder verhindert das Laden.

Wann eine Dateibearbeitung besser als ein Befehl ist

  • Cheats sind deaktiviert und sollen nicht nur für einen einzelnen Befehl ein- und wieder ausgeschaltet werden.
  • Die Welt lädt nicht. Eine Regel wie doImmediateRespawn kann vor dem ersten Beitritt gesetzt werden.
  • Du bereitest eine Vorlagenwelt vor, die für mehrere Server kopiert wird und ihre Regeln bereits enthalten soll.
  • Ein Plugin hat eine Regel geändert und du möchtest den tatsächlich gespeicherten Wert statt der Ausgabe eines Befehls prüfen.
  • Viele Änderungen. Ein Dutzend Regeln in mehreren Welten lässt sich in Dateien schneller setzen als im Chat.

Stoppe wie bei jeder Änderung von level.dat zuerst den Server. Eine laufende Welt schreibt die Datei beim Speichern neu und verwirft deine Änderung.

Häufig gestellte Fragen

Warum wird meine Spielregel in Java als String gespeichert?

Java speichert jede Spielregel als String, auch boolesche Werte und Zahlen. Schreibe "true" und nicht ein Byte mit dem Wert 1.

Warum ist die Regel in Bedrock ein Byte?

Bedrock speichert Schalter als Byte-Tags im Root-Tag und numerische Regeln als Integer. Es gibt kein Compound GameRules.

Eine Regel fehlt vollständig in der Datei.

Dann verwendet sie ihren Standardwert. Füge den Tag mit dem exakten Namen und richtigen Typ hinzu, damit die Welt deinen Wert verwendet.

Werden Spielregeln mit einem Weltordner kopiert?

Ja. Sie liegen in level.dat. Eine kopierte Welt übernimmt sie zusammen mit ihrem veralteten Weltnamen.
