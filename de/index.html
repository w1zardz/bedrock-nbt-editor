Jede NBT-Datei, die Minecraft schreibt

NBT (Named Binary Tag) ist ein Format mit mehreren Kodierungen. Jede Minecraft-Edition, jeder Launcher und jeder Serverkern verwendet eine andere Kombination davon. Dieser Editor unterstützt sie alle und erkennt die richtige Variante anhand der Bytes. Du musst daher vor dem Öffnen nicht wissen, um welche Variante es sich handelt.

So bearbeitest du eine NBT-Datei

  1. Kopiere die Datei vom Server oder Gerät. Java-Server speichern sie unter world/, Bedrock-Server unter worlds/YourWorld/ und Android unter games/com.mojang/minecraftWorlds/<id>/. Stoppe zuerst den Server, damit die Datei während des Kopierens nicht geschrieben wird.
  2. Ziehe sie in den Editor. Die Anzeige über der Baumansicht nennt die erkannte Edition, Kodierung und Komprimierung sowie bei Bedrock die Speicherversion aus dem Header.
  3. Bearbeite die Daten. Tippe einen Wert an, um ihn direkt zu ändern. Mit der Suche springst du zu einem Tag-Namen oder -Wert. Mit + fügst du Tags zu Compounds oder Listen hinzu, mit × entfernst du sie.
  4. Speichern und herunterladen. Ausgabeformat und Komprimierung entsprechen standardmäßig der eingelesenen Datei. Eine reine Bearbeitung behält das Format daher bytegenau bei.
  5. Kopiere die Datei zurück und starte neu. Bewahre das Original als Sicherung auf, bis die Welt einmal fehlerfrei geladen wurde.

Besonderheiten dieses Editors

Fünf Kodierungen, ein Ablagebereich

Java Big-Endian, Bedrock Little-Endian, Bedrock-Varint-Netzwerk-NBT, Netzwerk-NBT mit namenlosem Root-Tag ab Java 1.20.2 und Bedrocks level.dat mit Header. Die Variante wird erkannt, nicht geraten.

gzip und zlib im Browser

Dekomprimierung und erneute Komprimierung nutzen die native Compression Streams API. Dadurch wird eine Java-Datei level.dat wieder zu einer Datei, die das Spiel unverändert akzeptiert.

Echte 64-Bit-Long-Werte

TAG_Long-Werte werden als BigInt gehalten. Welt-Seeds und UUID-Hälften überstehen die Bearbeitung, statt durch Gleitkomma-Rundung verfälscht zu werden. Genau daran scheitern viele NBT-Werkzeuge im Browser.

Korrekte Zeichenkodierung

Java schreibt modifiziertes UTF-8 (CESU-8), Bedrock normales UTF-8. Der Editor kodiert passend zur Edition, sodass Emojis und nichtlateinische Weltnamen erhalten bleiben.

Für große Dateien ausgelegt

Arrays liegen in typisierten Arrays, und die Baumansicht rendert verzögert jeweils 200 Einträge. Ein Megabyte Chunk-NBT lässt sich öffnen, ohne den Tab einzufrieren.

Suche in der gesamten Baumansicht

Finde jeden Tag anhand seines Namens oder Werts an beliebiger Stelle in der Datei und springe mit geöffnetem Pfad direkt dorthin.

SNBT-Export

Exportiere den gesamten Baum als SNBT – die von /data und Datapacks verwendete Textform – zum Vergleichen, Teilen oder Einfügen in einen Befehl.

Formatkonvertierung

Lies eine Bedrock-Datei und schreibe Java Big-Endian mit gzip oder umgekehrt. Das ist für Protokollarbeit, Tests und Werkzeuge nützlich.

Keine Daten verlassen dein Gerät

Die Datei wird mit FileReader gelesen, in JavaScript verarbeitet und als In-Memory-Blob zurückgegeben. Es gibt keinen Upload-Endpunkt.

Unterstützte Serversoftware – ohne Einschränkung

NBT wird vom Spiel geschrieben, nicht von der Serverimplementierung. Jeder Kern, der eine Minecraft-Welt speichert, nutzt daher eine der Kodierungen, die dieser Editor liest. Die folgende Liste ist vollständig gemeint und keine Werbeliste: Ein Kern schreibt eine Welt in der Struktur von Vanilla, weil der Client am anderen Ende sie lesen können muss.

Bedrock Edition – Little-Endian-NBT, 8-Byte-Header in level.dat

Bedrock Dedicated Server (BDS), PocketMine-MP (PM3, PM4, PM5), Nukkit, Nukkit-MOT, PowerNukkitX, Cloudburst Server, Dragonfly, Endstone, LeviLamina und BDSX, Allay, JukeboxMC, GoMint, Sculk, ElementZero, LiteLoaderBDS sowie die Clients MCPE und MCBE auf Android, iOS, Windows, Konsolen und Switch. Vanilla, CraftBukkit, Spigot, Paper, Purpur, Pufferfish, Folia, Leaves, Gale, Petal, Airplane, Sponge (SpongeVanilla, SpongeForge), Fabric, Quilt, Forge, NeoForge, Mohist, Arclight, Magma, Ketting, Banner, Cardboard, Glowstone, Thermos, Uberbukkit und jeder andere Fork, Modpack-Server oder alte Legacy-Build. Wenn er world/level.dat schreibt, kann dieser Editor die Datei öffnen – Details dazu.

Proxys und Bridges

Geyser, WaterdogPE, Waterfall, Velocity und BungeeCord verwalten keine Welten, sondern übertragen NBT über das Netzwerk. Mitschnitte dieser Verbindungen sind Netzwerk-NBT: Varint Little-Endian auf der Bedrock-Seite und Big-Endian mit namenlosem Root-Tag ab Java 1.20.2. Beide lassen sich hier direkt öffnen.

Nicht aufgeführte Software

Eigene Forks, private Serverkerne, Lehrprojekte oder selbst geschriebene Server: Wenn die Datei NBT enthält, erkennt der Editor eine der fünf Kodierungen und öffnet sie. Die Erkennung hängt nicht vom Namen eines Serverkerns ab.

Parser im eigenen Code verwenden

Die Seite stellt ihre Engine unter window.NBT bereit. Derselbe Parser wie in der Oberfläche lässt sich daher über die Browserkonsole steuern oder in einem Userscript wiederverwenden:

const bytes = new Uint8Array(await file.arrayBuffer());
const { root, format, compression, headerVersion } = await NBT.read(bytes);

root.value.find(t => t.name === "LevelName").value = "New World";

const out = await NBT.write(root, format, { compression, headerVersion });

Tags sind einfache Objekte – { type, name, value, listType } –, Arrays sind Int8Array, Int32Array und BigInt64Array, Long-Werte sind BigInt. Die vollständige Referenz zum NBT-Format beschreibt jeden Tag-Typ und die Unterschiede zwischen den Kodierungen.

Häufig gestellte Fragen

Ist dieser NBT-Editor kostenlos?

Ja, der Quellcode steht zudem unter der MIT-Lizenz. Es gibt weder einen kostenpflichtigen Tarif noch eine Anmeldung oder ein Upload-Limit, weil überhaupt keine Serverkomponente vorhanden ist. Der gesamte Editor besteht aus einer statischen Seite und zwei Asset-Dateien.

Funktioniert er mit der Java Edition und der Bedrock Edition?

Mit beiden. Dateien der Java Edition sind Big-Endian und meist mit gzip komprimiert. Bedrock-Dateien sind Little-Endian, und level.dat enthält zusätzlich einen 8-Byte-Header. Der Editor erkennt die Variante und schreibt sie beim Speichern im gleichen Format zurück.

Wird meine Weltdatei irgendwo hochgeladen?

Nein. Die Datei wird lokal mit der FileReader API gelesen, und der Download entsteht aus einem In-Memory-Blob. Sobald die Seite geladen ist, funktioniert sie auch nach dem Trennen der Netzwerkverbindung.

Kann ich den Editor unter Android oder iOS verwenden?

Ja. Das Layout ist für Mobilgeräte ausgelegt, mit 44 px großen Tippflächen und einer fixierten Aktionsleiste. Unter Android kannst du eine Weltdatei direkt im Dateimanager auswählen. Unter iOS muss sie wegen der Sandbox zuerst in der Dateien-App liegen.

Was ist der Unterschied zwischen NBT und SNBT?

NBT ist die binäre Kodierung, in der Minecraft Daten auf dem Datenträger speichert. SNBT ist die Textform und entspricht der Syntax in Befehlen wie /data merge. Dieser Editor liest binäres NBT und exportiert SNBT, sodass sich zwei Dateien leicht vergleichen oder Strukturen in einen Befehl einfügen lassen.

Welche Werkzeuge ersetzt dieser Editor?

Desktop-NBT-Editoren wie NBTExplorer sowie verschiedene Webwerkzeuge, die nur eine Edition unterstützen. Der Online-Vergleich mit NBTExplorer zeigt, welche Funktionen vorhanden sind und welche nicht.
