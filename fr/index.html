Éditeur NBT Bedrock — compatible aussi avec Java Edition

Compatible avec Minecraft Bedrock Edition et Java Edition, ainsi qu'avec tous leurs logiciels serveur, courants ou non : Vanilla, Paper, Spigot, Purpur, Folia, Fabric, Forge, NeoForge, Mohist, Sponge, Bedrock Dedicated Server, PocketMine-MP, Nukkit, PowerNukkitX, Cloudburst, Dragonfly, Endstone, LeviLamina et les autres. Liste complète.

Bedrock Edition est prise en charge avec tous ses logiciels serveur, tout comme Java Edition, y compris avec les logiciels les moins courants. Déposez un fichier level.dat, playerdata, .nbt, .mcstructure, .schem ou .schematic dans la zone ci-dessous, modifiez n'importe quelle balise dans l'arborescence, puis téléchargez-le dans exactement le même format binaire. L'ordre des octets, l'en-tête et la compression sont détectés automatiquement. Tout s'exécute dans votre navigateur : aucun envoi, aucun compte et aucune installation.

Tous les fichiers NBT écrits par Minecraft

NBT (Named Binary Tag) est un format qui possède plusieurs encodages. Chaque édition, lanceur et logiciel serveur Minecraft en utilise une combinaison différente. Cet éditeur les prend tous en charge et détermine le bon directement à partir des octets : vous n'avez donc pas besoin de connaître la variante d'un fichier avant de l'ouvrir.

Comment modifier un fichier NBT

  1. Récupérez le fichier sur le serveur ou l'appareil. Les serveurs Java le placent dans world/, les serveurs Bedrock dans worlds/YourWorld/ et Android dans games/com.mojang/minecraftWorlds/<id>/. Arrêtez d'abord le serveur pour éviter toute écriture pendant la copie.
  2. Déposez-le dans l'éditeur. Le badge au-dessus de l'arborescence indique ce qui a été détecté : édition, encodage, compression et, pour Bedrock, version de stockage extraite de l'en-tête.
  3. Modifiez. Touchez une valeur pour la changer sur place. Utilisez la recherche pour atteindre une balise par son nom ou sa valeur, + pour ajouter des balises à un composé ou une liste, et × pour les supprimer.
  4. Enregistrez et téléchargez. Les sélecteurs de format de sortie et de compression reprennent par défaut ceux du fichier d'origine. Une simple modification produit donc un aller-retour fidèle au niveau des octets.
  5. Remettez le fichier en place et redémarrez. Conservez l'original comme sauvegarde jusqu'à ce que le monde ait été chargé une fois et vérifié.

Ce qui distingue cet éditeur

Cinq encodages dans une seule zone

Java gros-boutiste, Bedrock petit-boutiste, NBT réseau Bedrock en varint, NBT réseau à racine sans nom de Java 1.20.2+, et level.dat Bedrock avec en-tête. Ils sont détectés, pas devinés.

gzip et zlib dans le navigateur

La décompression et la recompression utilisent l'API native Compression Streams. Un level.dat Java ressort donc sous une forme acceptée telle quelle par le jeu.

Vrais entiers longs sur 64 bits

Les valeurs TAG_Long sont conservées sous forme de BigInt. Les graines de monde et les moitiés d'UUID ne sont pas altérées par l'arrondi des nombres à virgule flottante, contrairement à de nombreux outils NBT pour navigateur.

Encodage correct des chaînes

Java utilise l'UTF-8 modifié (CESU-8), tandis que Bedrock utilise l'UTF-8 standard. L'éditeur choisit l'encodage de l'édition, ce qui préserve les emoji et les noms de monde non latins.

Conçu pour les fichiers volumineux

Les tableaux sont stockés dans des tableaux typés et l'arborescence est rendue à la demande, par groupes de 200 entrées. Un mégaoctet de NBT de chunk s'ouvre sans bloquer l'onglet.

Recherche dans toute l'arborescence

Recherchez une balise par son nom ou sa valeur partout dans le fichier et accédez-y directement avec son chemin développé.

Export SNBT

Exportez toute l'arborescence en SNBT, la forme textuelle utilisée par /data et les datapacks, afin de comparer, partager ou coller les données dans une commande.

Conversion de format

Lisez un fichier Bedrock et écrivez-le en gzip gros-boutiste Java, ou inversement. Utile pour les protocoles, les tests et les outils.

Aucune donnée ne quitte votre appareil

Le fichier est lu avec FileReader, analysé en JavaScript, puis rendu sous forme de blob en mémoire. Aucun point de terminaison d'envoi n'existe.

Tous les logiciels serveur sont pris en charge

Le NBT est écrit par le jeu, pas par l'implémentation du serveur. Tout logiciel qui stocke un monde Minecraft emploie donc l'un des encodages lus par cet éditeur. La liste complète figure ci-dessous. Il ne s'agit pas d'une liste commerciale : un logiciel qui écrit un monde reprend la structure de Vanilla, car le client situé à l'autre extrémité doit pouvoir la lire.

Bedrock Edition — NBT petit-boutiste, en-tête level.dat de 8 octets

Bedrock Dedicated Server (BDS), PocketMine-MP (PM3, PM4, PM5), Nukkit, Nukkit-MOT, PowerNukkitX, Cloudburst Server, Dragonfly, Endstone, LeviLamina et BDSX, Allay, JukeboxMC, GoMint, Sculk, ElementZero, LiteLoaderBDS, ainsi que les clients MCPE et MCBE eux-mêmes sur Android, iOS, Windows, console et Switch. Même worlds/<World>/level.dat, même en-tête, mêmes balises : consultez la procédure côté serveur.

Java Edition — NBT gros-boutiste, gzip

Vanilla, CraftBukkit, Spigot, Paper, Purpur, Pufferfish, Folia, Leaves, Gale, Petal, Airplane, Sponge (SpongeVanilla, SpongeForge), Fabric, Quilt, Forge, NeoForge, Mohist, Arclight, Magma, Ketting, Banner, Cardboard, Glowstone, Thermos, Uberbukkit et tout autre dérivé, serveur de modpack ou ancienne version. S'il écrit world/level.dat, cet éditeur l'ouvre : voir les détails.

Proxys et passerelles

Geyser, WaterdogPE, Waterfall, Velocity et BungeeCord ne possèdent pas les mondes ; ils transportent le NBT sur le réseau. Les captures issues de leurs connexions sont du NBT réseau : varint petit-boutiste côté Bedrock et racine sans nom gros-boutiste côté Java 1.20.2+. Les deux s'ouvrent directement ici.

Logiciels absents de cette liste

Dérivés personnalisés, logiciels privés, projets pédagogiques ou serveur écrit par vos soins : si le fichier est en NBT, l'éditeur détecte lequel des cinq encodages il utilise et l'ouvre. Rien ici ne dépend du nom du logiciel.

Utiliser l'analyseur depuis votre propre code

La page expose son moteur dans window.NBT. Le même analyseur que celui de l'interface peut donc être piloté depuis la console du navigateur ou réutilisé dans un script utilisateur :

const bytes = new Uint8Array(await file.arrayBuffer());
const { root, format, compression, headerVersion } = await NBT.read(bytes);

root.value.find(t => t.name === "LevelName").value = "New World";

const out = await NBT.write(root, format, { compression, headerVersion });

Les balises sont des objets simples — { type, name, value, listType } —, les tableaux sont des Int8Array, Int32Array et BigInt64Array, et les entiers longs des BigInt. La référence du format NBT décrit chaque type de balise et les différences entre les encodages.

Questions fréquentes

Cet éditeur NBT est-il gratuit ?

Oui, et son code source est disponible sous licence MIT. Il n'existe ni offre payante, ni inscription, ni quota d'envoi, car aucun composant serveur n'est utilisé : l'éditeur complet se compose d'une page statique et de deux fichiers de ressources.

Fonctionne-t-il avec Java Edition et Bedrock Edition ?

Avec les deux. Les fichiers Java Edition sont gros-boutistes et généralement compressés avec gzip ; ceux de Bedrock sont petit-boutistes, et level.dat contient un en-tête supplémentaire de 8 octets. L'éditeur détecte la variante reçue et réécrit la même lors de l'enregistrement.

Mon fichier de monde est-il envoyé quelque part ?

Non. Le fichier est lu localement avec l'API FileReader, et le téléchargement est produit à partir d'un blob en mémoire. Une fois la page chargée, vous pouvez vous déconnecter du réseau : elle continue de fonctionner.

Puis-je l'utiliser sur Android ou iOS ?

Oui. La mise en page est conçue d'abord pour les mobiles, avec des zones tactiles de 44 px et une barre d'actions fixe. Sous Android, vous pouvez choisir un fichier de monde directement dans un gestionnaire de fichiers. Sous iOS, il doit d'abord se trouver dans l'app Fichiers en raison du cloisonnement.

Quelle est la différence entre NBT et SNBT ?

NBT est l'encodage binaire que Minecraft stocke sur le disque. SNBT est sa forme textuelle, dont la syntaxe est utilisée dans des commandes comme /data merge. Cet éditeur lit le NBT binaire et peut exporter du SNBT, ce qui facilite la comparaison de deux fichiers ou le collage d'une structure dans une commande.

Quels outils cet éditeur remplace-t-il ?

Les éditeurs NBT de bureau tels que NBTExplorer, ainsi que les outils web spécialisés qui ne traitent qu'une seule édition. Consultez la comparaison avec NBTExplorer en ligne pour connaître les fonctions reprises et les différences.
