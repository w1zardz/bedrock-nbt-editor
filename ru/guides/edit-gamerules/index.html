Изменение игровых правил в level.dat

Поддерживает Minecraft Bedrock Edition и Java Edition и все серверные ядра для обеих редакций, популярные и малоизвестные: Vanilla, Paper, Spigot, Purpur, Folia, Fabric, Forge, NeoForge, Mohist, Sponge, Bedrock Dedicated Server, PocketMine-MP, Nukkit, PowerNukkitX, Cloudburst, Dragonfly, Endstone, LeviLamina и остальные. Полный список.

Игровые правила хранятся в level.dat, поэтому их можно менять без загрузки мира и включения читов. Это полезно, если мир не запускается, читы отключены или вы готовите копию мира до входа игроков. Java хранит правила как строки в составном теге GameRules, а Bedrock — каждое отдельно в корневом байтовом теге с именем в нижнем регистре.

keepInventorydoDaylightCyclemobGriefingcommandBlockOutputrandomTickSpeed

Java: составной тег GameRules со строками

В Java Edition путь Data → GameRules содержит по одному TAG_String для каждого правила. Ключ точно совпадает с именем, используемым командой /gamerule, а значение записывается текстом: "true", "false" или числом. Правила, которые никогда не задавались в мире, просто отсутствуют и получают значения по умолчанию. Добавление тега с правильным именем и строковым значением работает так же, как выполнение команды.

ПравилоЗначениеЭффект
keepInventory"true"Сохранять предметы после смерти
doDaylightCycle"false"Остановить смену времени суток
doWeatherCycle"false"Остановить смену погоды
mobGriefing"false"Запретить криперам и эндерменам изменять блоки
doMobSpawning"false"Остановить естественное появление мобов

Регистр важен. keepinventory в файле Java — не тот же тег, что keepInventory, поэтому он будет проигнорирован.

Bedrock: отдельные байтовые теги в нижнем регистре

Bedrock не группирует правила. Каждое из них представляет собой TAG_Byte в корне level.dat с именем в нижнем регистре и значением 1 или 0: keepinventory, domobspawning, domobloot, dodaylightcycle, doweathercycle, mobgriefing, firedamage, falldamage, drowningdamage, pvp, showcoordinates, commandblockoutput, sendcommandfeedback, naturalregeneration, tntexplodes, respawnblocksexplode, showdeathmessages, doimmediaterespawn. Числовые правила, например randomtickspeed и functioncommandlimit, имеют тип TAG_Int.

Чтобы задать отсутствующее правило, добавьте тег правильного типа: Byte для переключателя, Int для числа. Правило с неверным типом игнорируется или мешает загрузке мира.

Когда лучше отредактировать файл, а не вводить команду

  • Читы отключены, и вы не хотите включать и снова отключать их ради одной команды.
  • Мир не загружается: правило вроде doImmediateRespawn можно задать до первого входа.
  • Вы готовите шаблон мира для копирования на несколько серверов и хотите сохранить правила в копии.
  • Плагин изменил правило, и нужно увидеть фактически сохранённое значение, а не результат команды.
  • Массовое редактирование. Десяток правил в нескольких мирах быстрее задать в файлах, чем через чат.

Сначала остановите сервер, как при любом изменении level.dat: работающий мир перезаписывает файл при сохранении и отменяет правку.

Часто задаваемые вопросы

Почему в Java игровое правило хранится как строка?

Java хранит все игровые правила как строки, включая логические и числовые. Запишите "true", а не байт 1.

Почему в Bedrock используется байт?

Bedrock хранит переключатели в виде байтовых тегов в корне, а числовые правила — в виде int. Составного тега GameRules нет.

Правило полностью отсутствует в файле.

Это означает, что действует значение по умолчанию. Добавьте тег с точным именем и правильным типом, и мир будет использовать заданное значение.

Копируются ли игровые правила вместе с папкой мира?

Да. Они хранятся в level.dat, поэтому скопированный мир наследует их вместе с устаревшим именем мира.
