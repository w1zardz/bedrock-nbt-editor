Справочник по формату NBT

Поддерживает Minecraft Bedrock Edition и Java Edition и все серверные ядра для обеих редакций, популярные и малоизвестные: Vanilla, Paper, Spigot, Purpur, Folia, Fabric, Forge, NeoForge, Mohist, Sponge, Bedrock Dedicated Server, PocketMine-MP, Nukkit, PowerNukkitX, Cloudburst, Dragonfly, Endstone, LeviLamina и остальные. Полный список.

NBT (Named Binary Tag) — двоичный древовидный формат Minecraft: тег состоит из однобайтового типа, имени с префиксом длины и полезной нагрузки, а составные теги вкладываются друг в друга до закрывающего байта TAG_End. В Java и Bedrock используются 13 типов тегов и пять кодировок. На этой странице описаны все варианты, а редактор выше позволяет проверить сведения на реальном файле.

Файл содержит единственный корневой TAG_Compound: один байт типа 0x0A, имя, затем содержимое составного тега. Именованные теги встречаются только внутри составных тегов, а элементы списков содержат лишь полезную нагрузку, поэтому список однороден.

В кодировке varint значения TAG_Short, TAG_Float и TAG_Double сохраняют фиксированную ширину и порядок little-endian. Только TAG_Int и TAG_Long становятся zigzag varint, а длины массивов и списков кодируются так же, как TAG_Int. Длины строк представляют собой беззнаковые varint, поэтому ограничение фиксированных кодировок в 65535 байт также снимается.

Строки: модифицированный UTF-8 и UTF-8

Java сериализует строки через DataOutputStream.writeUTF, то есть в модифицированном UTF-8: символ NUL записывается как C0 80, а не 00, а символы за пределами основной многоязычной плоскости — как две трёхбайтовые суррогатные половины (CESU-8) вместо одной четырёхбайтовой последовательности. Bedrock использует стандартный UTF-8. Инструмент, который применяет одну кодировку для обоих вариантов, при сохранении повреждает эмодзи и часть текста CJK. Этот редактор кодирует строки в соответствии с форматом, поэтому имя мира с эмодзи сохраняется без изменений.

Сжатие

Сам NBT не сжат: это определяет контейнер. Файлы Java обычно используют gzip (сигнатура 1F 8B), данные чанков внутри файлов регионов — zlib (сигнатура 78 01, 78 9C или 78 DA), а Bedrock хранит level.dat и файлы структур без сжатия. Формат определяется по сигнатуре, поэтому один парсер обрабатывает все три варианта. Сохранение с неверным сжатием — самая частая причина, по которой отредактированный вручную мир не загружается.

Минимальный файл, байт за байтом

Канонический файл hello_world.nbt: корневой составной тег с именем hello world, содержащий один строковый тег name со значением Bananrama. В кодировке Java big-endian:

0A                          TAG_Compound
00 0B 68 65 6C 6C 6F 20 77 6F 72 6C 64   name length 11, "hello world"
   08                       TAG_String
   00 04 6E 61 6D 65        name length 4, "name"
   00 09 42 61 6E 61 6E 72 61 6D 61      value length 9, "Bananrama"
00                          TAG_End

В кодировке Bedrock little-endian этот же документ отличается только порядком байтов в двух полях длины: 0B 00 вместо 00 0B. В сетевом NBT Bedrock длины становятся однобайтовыми varint 0B и 04 без заполнения. Загрузите любой из трёх вариантов в редактор выше, и он определит формат.

SNBT

SNBT — текстовое представление NBT, которое принимают команды: /data merge entity @s {Invulnerable:1b}. Суффиксы типов позволяют сохранять данные без потерь: b — byte, s — short, L — long, f — float, d — double, без суффикса — int. Типизированные массивы записываются как [B;…], [I;…], [L;…]. Редактор экспортирует SNBT из любого загруженного файла, после чего две версии мира можно сравнить обычным текстовым diff.

Часто задаваемые вопросы

Существует ли официальная спецификация NBT?

У Mojang нет формальной спецификации. Формат был описан Notch в 2010 году и с тех пор поддерживается сообществом. Идентификаторы тегов и структура на этой странице соответствуют данным, которые игра читает и записывает сейчас.

Почему Bedrock использует little-endian?

Движок Bedrock написан на C++ и рассчитан на оборудование с порядком little-endian, поэтому значения хранятся в нативном порядке. Сериализация Java использует big-endian, поскольку это определено контрактом Java DataOutput.

Что такое кодировка zigzag varint?

Это способ записывать целые числа минимальным числом байтов и при этом компактно хранить отрицательные значения: знак переносится в младший бит, поэтому −1 кодируется как 1, а 1 — как 2. Протокол Bedrock использует эту кодировку для int и long.

Может ли TAG_List содержать разные типы?

Нет. Список объявляет один тип элементов, и каждая запись должна ему соответствовать. Для смешанных данных нужен список составных тегов.

Какова максимальная длина строки?

В фиксированных кодировках — 65535 байт, поскольку поле длины представляет собой unsigned short. У сетевой кодировки varint практического ограничения нет.
