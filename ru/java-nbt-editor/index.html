Редактор NBT для Java Edition

Поддерживаются Minecraft Bedrock Edition и Java Edition, а также все их серверные ядра, популярные и редкие: Vanilla, Paper, Spigot, Purpur, Folia, Fabric, Forge, NeoForge, Mohist, Sponge, Bedrock Dedicated Server, PocketMine-MP, Nukkit, PowerNukkitX, Cloudburst, Dragonfly, Endstone, LeviLamina и остальные. Полный список.

Minecraft Java Edition хранит данные в NBT с порядком big-endian, почти всегда со сжатием gzip. Перетащите ниже любой файл Java — level.dat, UUID-файл playerdata, servers.dat, структуру .nbt или схему WorldEdit. Редактор распакует файл, разберёт его как big-endian и запишет со сжатием gzip, чтобы игра приняла его без изменения формата.

Как Java кодирует NBT

  • Big-endian. В каждом целом числе и числе с плавающей точкой сначала хранится старший байт, как в DataOutputStream Java.
  • Именованный корень. Файл начинается с типа тега 0x0A, затем идёт имя корня в UTF-8 с префиксом длины; в level.dat оно традиционно пустое.
  • Модифицированный UTF-8. Строки используют кодирование writeUTF Java: двухбайтовую длину, NUL в виде C0 80 и символы вне основной плоскости, разделённые на две трёхбайтовые половины (CESU-8). Инструмент, который считает это обычным UTF-8, искажает эмодзи в названиях миров; этот редактор кодирует их правильно.
  • По умолчанию gzip. NbtIo.readCompressed ожидает поток gzip. Несжатые файлы открываются в некоторых инструментах, но не в игре.
  • Безымянный корень в сети. Начиная с 1.20.2 протокол передаёт NBT без имени корня. Такие дампы пакетов определяются здесь как сетевая Java.

Paper, Spigot, Fabric, Forge — одинаковые файлы

Форки и загрузчики модов меняют работу сервера, но не формат записи мира. Paper, Purpur, Pufferfish, Folia, Fabric, Quilt, Forge, NeoForge, Mohist, Arclight и Sponge используют структуру NBT Vanilla, поэтому всё на этой странице применимо к ним без изменений. Форки добавляют рядом с миром свои файлы, например paper-world.yml и конфигурации модов, но они имеют формат YAML или TOML и не относятся к NBT.

Моды и плагины могут добавлять собственные Compound в level.dat или playerdata. Эти теги открываются как любые другие; не меняйте их, если не знаете, как мод их использует.

DataVersion и миграция версий

Миры Java содержат целое число DataVersion, которое обозначает формат мира и увеличивается в каждом снапшоте. Несколько ориентиров: 1.16.5 — 2586, 1.17.1 — 2730, 1.18.2 — 2975, 1.19.4 — 3337, 1.20.4 — 3700, 1.21 — 3953. Именно из-за этого тега нельзя открыть мир в клиенте старше того, который его записал. Уменьшение значения вручную не понижает версию данных чанков, а только снимает защиту. Читайте тег, чтобы определить записавшую мир версию; не меняйте его для принудительного понижения.

Частые вопросы

Можно открыть level.dat Java, который не загружается в игре?

Обычно да. Редактор терпимее игры к лишним байтам в конце и точно сообщает, где остановился разбор усечённого файла. Если он тоже отказывает, попробуйте level.dat_old — предыдущее автосохранение.

Поддерживается сетевой NBT из версии 1.20.2 и новее?

Да. Начиная с 1.20.2 протокол не передаёт имя корня. Дамп такого вида определяется как формат сетевая Java; его можно сохранить как сетевой NBT или как обычный файл с именованным корнем.

Можно изменить чанк из файла региона .mca?

NBT чанка можно изменить после извлечения из контейнера региона. Сам .mca состоит из индекса и множества сжатых zlib данных чанков, а редактор работает с одним документом NBT, но не с контейнером.

Редактирование playerdata повредит данные игрока?

Только если сервер работает во время редактирования: он хранит состояние игрока в памяти и записывает его при выходе, заменяя ваш файл. Отключите игрока, измените файл и разрешите ему подключиться снова. См. редактор playerdata.

Для level.dat требуется gzip?

Загрузчик Vanilla читает gzip. При сохранении выберите сжатие gzip; оно используется по умолчанию, если исходный файл был сжат так же. После этого игра примет файл.
