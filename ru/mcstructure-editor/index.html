Редактор .mcstructure — структуры Bedrock

Поддерживаются Minecraft Bedrock Edition и Java Edition, а также все популярные и малоизвестные серверные ядра для обеих версий: Vanilla, Paper, Spigot, Purpur, Folia, Fabric, Forge, NeoForge, Mohist, Sponge, Bedrock Dedicated Server, PocketMine-MP, Nukkit, PowerNukkitX, Cloudburst, Dragonfly, Endstone, LeviLamina и другие. Полный список.

Файл .mcstructure — несжатый little-endian NBT, записанный структурным блоком Bedrock. Откройте его, чтобы просмотреть размер, палитру и индексы блоков, данные блочных сущностей, изменить теги и скачать файл в исходном кодировании. Это удобно авторам аддонов и карт, когда структуру нужно исправить без повторного открытия мира.

Содержимое .mcstructure

ТегТипСодержимое
format_versionIntВерсия формата структуры; в текущих файлах — 1
sizeСписок IntРазмеры области по X, Y, Z
structure_world_originСписок IntМесто создания структуры в мире
structureCompoundКонтейнер для следующих данных
structure.block_indicesСписок массивов Int[]Два слоя индексов палитры, обычно блоки и waterlogging; -1 означает «оставить существующий блок»
structure.entitiesСписок CompoundСущности, сохранённые вместе со структурой
structure.palette.default.block_paletteСписок CompoundВсе состояния блоков: name, states, version
structure.palette.default.block_position_dataCompoundNBT блочных сущностей по линейному индексу позиции

Индексы block_indices идут по X, затем Z и Y: (x * sizeZ + z) * sizeY + y указывает элемент палитры. Так можно исправить отдельный блок без повторного создания структуры.

Типичные изменения

  • Заменить тип блока во всей структуре: измените одну запись block_palette, и все позиции с этим индексом обновятся.
  • Исправить состояние блока, например неверный facing или случайный waterlogged, внутри states.
  • Удалить случайно сохранённые сущности из списка entities.
  • Исправить данные блочной сущности: содержимое сундука, текст таблички или параметры спавнера в block_position_data.
  • Проверить версию записей палитры, если после обновления игры импортируются неверные блоки.

Расположение файлов

Структурные блоки сохраняют файлы в папке structures/ внутри мира под именами <namespace>_<name>.mcstructure. Наборы поведения хранят их в своей папке structures/ и загружают по пространству имён. Формат одинаков.

Аналог Java Edition — сжатый gzip big-endian файл структуры .nbt с другой схемой тегов. Он описан на странице редактора Java и тоже открывается здесь.

Частые вопросы

Можно преобразовать .mcstructure в структуру .nbt Java?

Редактор может записать байты как big-endian gzip, но схема тегов различается: Java использует palette/blocks с другими ключами и именами блоков. Такой файл читается как NBT, но не является корректной структурой Java.

Почему .mcstructure не сжат?

Bedrock записывает структуры как несжатый little-endian NBT. Это нормально; редактор определяет его как Bedrock без заголовка.

Что означает индекс -1 в block_indices?

Эта позиция не изменяется структурой, поэтому при размещении сохраняется существующий в мире блок.

Можно изменить размер структуры через size?

Не отдельно: block_indices должен содержать по одной записи на каждую позицию, а длина массива — точно соответствовать новому объёму. Одно изменение size создаст файл, который игра отклонит.
