.mcstructure редактор — файлы структур Bedrock

Поддерживаются Minecraft Bedrock Edition и Java Edition, а также все популярные и малоизвестные серверные ядра для обеих версий: Vanilla, Paper, Spigot, Purpur, Folia, Fabric, Forge, NeoForge, Mohist, Sponge, Bedrock Dedicated Server, PocketMine-MP, Nukkit, PowerNukkitX, Cloudburst, Dragonfly, Endstone, LeviLamina и другие. Полный список.

Файл .mcstructure содержит несжатые данные NBT с порядком байтов little-endian, записанные структурным блоком Bedrock. Перетащите файл ниже, чтобы прочитать размеры, палитру и индексы блоков, а также данные блочных сущностей, отредактировать их и скачать файл в прежней кодировке. Это позволяет авторам дополнений и карт исправить структуру, не открывая мир заново.

Что находится внутри .mcstructure

ТегТипСодержимое
format_versionIntВерсия формата структуры, в текущих файлах — 1
sizeList of IntРазмеры захваченного объёма по X, Y, Z
structure_world_originList of IntМесто захвата структуры в мире
structureCompoundЗдесь находятся все перечисленные ниже данные
structure.block_indicesList of Int[]Два слоя индексов палитры — обычно блоки и затопление водой; -1 означает "оставить содержимое позиции без изменений"
structure.entitiesList of CompoundСущности, захваченные вместе со структурой
structure.palette.default.block_paletteList of CompoundВсе уникальные состояния блоков: name, states, version
structure.palette.default.block_position_dataCompoundNBT блочных сущностей с плоским индексом позиции в качестве ключа

Индексы в block_indices идут по X, затем по Z и Y. Плоский индекс (x * sizeZ + z) * sizeY + y указывает на список палитры. Такое соответствие позволяет исправить один неверно заданный блок без повторного создания структуры.

Что обычно меняют

  • Заменяют тип блока во всей структуре, изменяя одну запись в block_palette: вместе с ней меняются все позиции, которые ссылаются на этот индекс.
  • Исправляют состояние блока, например неверный facing или случайный waterlogged в Compound states.
  • Удаляют случайно захваченные сущности, убирая записи из списка entities.
  • Восстанавливают данные блочных сущностей: содержимое сундуков, текст табличек и настройки спаунеров внутри block_position_data.
  • Проверяют версию в записях палитры, если после обновления игры структура импортируется с неверными блоками.

Где находятся файлы

Структурные блоки сохраняют файлы в папке мира structures/ с именами вида <namespace>_<name>.mcstructure. В наборах поведения они находятся в папке structures/ набора, откуда игра загружает их по пространству имён. Формат в обоих случаях одинаков, и оба варианта открываются здесь.

Аналог для Java Edition — файл структуры .nbt с порядком байтов big-endian и сжатием gzip. У него другая кодировка и структура тегов. Подробнее см. на странице редактора Java; этот редактор тоже открывает такие файлы.

Частые вопросы

Можно ли преобразовать .mcstructure в структуру Java .nbt?

Редактор может перекодировать байты в big-endian со сжатием gzip, но структура тегов отличается: в структурах Java используются palette/blocks с другими ключами и именами блоков. Перекодированный файл можно прочитать, но он не будет корректной структурой Java.

Почему мой файл .mcstructure не сжат?

Bedrock записывает файлы структур как необёрнутый NBT с порядком байтов little-endian, без gzip. Это нормально; редактор определит такой формат как необёрнутый Bedrock.

Что означает индекс -1 в block_indices?

Он отмечает позицию, которую структура не затрагивает, поэтому при размещении структуры существующий блок в мире сохраняется.

Можно ли изменить размер структуры через size?

Одного этого недостаточно: в block_indices приходится по одной записи на позицию, поэтому длина массива должна точно соответствовать новому объёму. Если изменить только size, игра отклонит файл.
