How to Use

  1. Find the file. Java server: world/level.dat, world/playerdata/<uuid>.dat. Bedrock server: worlds/YourWorld/level.dat. Mobile: games/com.mojang/minecraftWorlds/<id>/level.dat.
  2. Drag it onto the editor above, or tap Choose File. The badge tells you which edition and encoding was detected.
  3. Expand the tree and tap any value to edit it inline. Search by tag name or value to jump straight to it.
  4. Use + to add tags to any compound or list, × to remove them.
  5. Tap Save & Download. The output format and compression selects default to whatever the file arrived as — change them only if you are converting on purpose.
  6. Replace the original file (keep a backup) and restart the server or the game.

What People Fix With It

  • Wrong world name after copying a folder. LevelName still holds the old name, so the server list and console show duplicates. Editing the tag fixes it in seconds — the editor jumps to LevelName automatically when it finds one.
  • Locked out of your own world. Flip GameType / allowCommands, or set commandsAllowed on Bedrock, without loading the world.
  • Broken spawn point. Fix SpawnX, SpawnY, SpawnZ when spawn ends up inside terrain.
  • Game rules. Toggle keepInventory, doDaylightCycle, mobGriefing and friends directly in NBT.
  • Stuck player data. Clear Inventory, reset Pos, or drop a corrupted item stack from a playerdata file.
  • Version pinning. Inspect DataVersion or Bedrock lastOpenedWithVersion before migrating a world between cores.
  • Structure debugging. Read palettes and block entity data inside .nbt, .schem and .mcstructure files.

Java Edition: Vanilla, CraftBukkit, Spigot, Paper, Purpur, Pufferfish, Folia, Fabric, Quilt, Forge, NeoForge, Mohist, Arclight, Leaves, Sponge. They all persist worlds with big-endian gzip NBT, so the same level.dat and playerdata layout applies.

Frequently Asked Questions

What is NBT?

NBT (Named Binary Tag) is the binary tree format Minecraft uses for world metadata, chunks, entities, items and player data. Each tag has a type, a name and a payload, and compounds nest arbitrarily. Java Edition writes it big-endian; Bedrock Edition writes it little-endian, and over the network with varint-encoded integers.

What is level.dat?

The main metadata file of a world: name, game mode, difficulty, spawn position, game rules, world version, seed. In Java Edition it is a gzip-compressed big-endian NBT file with everything under a Data compound. In Bedrock Edition it is uncompressed little-endian NBT preceded by an 8-byte header (storage version + payload length), with the tags at the root.

Does it work with Minecraft Java Edition?

Yes. Drop a Java level.dat, playerdata/<uuid>.dat, .nbt structure or .schem and it opens. The file is decompressed, parsed big-endian, and written back gzip-compressed big-endian so the game accepts it unchanged.

Does it work with PocketMine-MP, Nukkit and BDS?

Yes. Those cores share the Bedrock world format: little-endian NBT and the 8-byte level.dat header, which the editor reads and rewrites exactly, including the storage version field. Bedrock network NBT (varint) is supported for protocol dumps.

Can I convert between Java and Bedrock NBT?

The byte encoding, yes — pick a different output format before saving and the same tag tree is re-serialized. The tag content differs between editions (Java nests everything under Data, Bedrock keeps it flat, block IDs and gamerule names differ), so a re-encoded file is not automatically a valid world for the other edition. Use it for tooling and inspection, not as a world converter.

Is my file uploaded to a server?

No. The file is read with the FileReader API, parsed in JavaScript, and the download is produced from an in-memory Blob. Nothing is transmitted. The page is static and works with the network disconnected.

How large a file can it handle?

Arrays are kept in typed arrays instead of JS arrays, and the tree only builds DOM for nodes you actually expand, paging 200 entries at a time. Multi-megabyte structure and chunk NBT opens fine; the practical limit is your device memory.

What if I break my file?

Keep a backup before you edit — the editor never touches your original, it only produces a new download, so a copy of the old file is always a valid rollback. If a value is out of range for its tag type the editor rejects it instead of writing a corrupt file.

Can I use this on a phone?

Yes. The layout is mobile-first with large tap targets, a fixed action bar and safe-area padding. On Android you can pick world files straight from a file manager; on iOS you need the file in the Files app first because of sandboxing.
