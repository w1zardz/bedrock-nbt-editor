playerdata Editor — Minecraft Player .dat Files

Supports Minecraft Bedrock Edition and Java Edition — and every server core for both, popular or obscure: Vanilla, Paper, Spigot, Purpur, Folia, Fabric, Forge, NeoForge, Mohist, Sponge, Bedrock Dedicated Server, PocketMine-MP, Nukkit, PowerNukkitX, Cloudburst, Dragonfly, Endstone, LeviLamina and the rest. Java Edition writes one gzip big-endian NBT file per player in world/playerdata/<uuid>.dat, holding inventory, ender chest, position, dimension, health, hunger, XP and attributes. Drop one below to fix a player stuck inside terrain, drop a crash-inducing item, or reset stats — with the server stopped, or at least with that player offline.

The tags in a player file

TagTypeWhat it is
PosList of DoubleX, Y, Z. The fix for a player stuck in a wall or below bedrock.
RotationList of FloatYaw and pitch.
DimensionString / IntWhich dimension the player logs into.
InventoryList of CompoundOne entry per stack: id, Count, Slot, components or tag.
EnderItemsList of CompoundEnder chest contents, same shape.
Health, foodLevel, XpLevel, XpTotalFloat / IntVitals and experience.
playerGameTypeIntPer-player game mode.
abilitiesCompoundFlying, invulnerable, walk and fly speed.
AttributesList of CompoundMax health, movement speed and other modifiers.
SpawnX/SpawnY/SpawnZ or respawnInt / CompoundPersonal respawn point, depending on version.
UUIDInt[4]The player's UUID as four ints in modern versions.

Item stacks changed shape in 1.20.5: custom data moved from a single tag compound to individual components. Both shapes open here; edit whichever your version writes.

Common repairs

  • Player stuck in terrain or falling forever. Set Pos to safe coordinates — three doubles, in order X, Y, Z — and clear Motion if it holds a huge value.
  • Client crashes on login. A malformed item is the usual cause. Remove the offending entry from Inventory rather than wiping the whole list.
  • Wrong dimension after a portal bug. Set Dimension back to minecraft:overworld and give Pos matching coordinates.
  • Stuck in spectator. Set playerGameType to 0 for survival, 1 for creative.
  • Attribute modifiers left by a removed plugin. Delete the stale entries in Attributes.

Do it with the player offline

The server holds player state in memory and writes it out on logout and on autosave. Editing the file while that player is online guarantees your changes are overwritten, and editing during a save can truncate the file. Take the player offline — or stop the server — copy the file, edit, and put it back before they reconnect. Keep the original until the login works.

Bedrock servers do not use this layout: player data lives in the world's LevelDB under keys such as player_<uuid>, whose values are little-endian NBT. Extract a value and it opens here as Bedrock raw.

Frequently Asked Questions

Which file is my player?

Files are named by UUID. Look the player's UUID up on a Mojang API viewer, or sort playerdata/ by modification time and match against the last login.

Can I give myself items by editing playerdata?

On your own server, yes — add an entry to the Inventory list with id, Count and Slot. On someone else's server that is an intrusion, and it will not work anyway because the live server rewrites the file.

Why did my edit disappear?

The server or the player was online when you edited. Player state in memory wins on the next save.

Is playerdata the same in Bedrock?

No. Bedrock keeps players inside the world LevelDB rather than in per-UUID files. The NBT inside those values is little-endian and opens here once extracted.
