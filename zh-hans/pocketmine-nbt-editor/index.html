世界名称重复问题

基岩版服务器管理员经常遇到这种情况：将 worlds/hub 复制为 worlds/hub2 以创建第二个竞技场后，控制台、世界管理器和所有报告世界名称的插件仍把两个世界都称为 hub。文件夹名称已经改变，但 LevelName 在 level.dat 内没有改变。

影响不只是显示问题。按内部名称查找世界的插件，如传送点、每世界配置和区域保护，可能解析到错误世界，世界管理命令也会产生歧义。解决方法是编辑该标签：将文件拖入上方，编辑器会直接跳到 LevelName 并打开编辑。

  1. 停止服务器。运行中的服务器会在保存时重写 level.dat，从而撤销编辑。
  2. 通过 SFTP 或面板文件管理器下载 worlds/<World>/level.dat。
  3. 将文件拖入编辑器，把 LevelName 改为新名称，然后保存。
  4. 上传并覆盖原文件，同时保留旧文件作为备份。
  5. 启动服务器，检查控制台中报告已加载世界的行。

各核心注意事项

核心世界路径说明
PocketMine-MP (PM5)worlds/<World>/默认世界由 level-name 设置，该项位于 server.properties；该值是文件夹名称，而 LevelName 是世界对自身的命名。
Nukkit / PowerNukkitXworlds/<World>/使用相同的基岩版布局；PNX 会在旁边添加自己的设置文件。
Bedrock Dedicated Serverworlds/<World>/level-name 在 server.properties 中选择文件夹；文件头存储版本通常为 10。
Cloudburst / Dragonflyworlds/<World>/读取相同的 level.dat；Dragonfly 可能在自己的数据库中保存额外状态。
WaterdogPE, Geyser—这些是代理，不保存世界；NBT 仅以网络 NBT 形式从中传递。

避免破坏生产服务器的操作方法

  • 备份整个世界文件夹，不要只备份 level.dat。这只需几秒，也是错误编辑后能够恢复的唯一保障。
  • 绝不要通过 SFTP 直接编辑在线文件。停止服务器后再下载、编辑和上传。服务器仍打开世界时原地编辑，可能产生截断文件。
  • 为新模式复制世界？复制后、服务器读取前立即更改 LevelName，避免任何组件缓存错误名称。
  • 加载后检查文件栏。其中会显示检测到的格式和存储版本。如果基岩版文件未报告为基岩版 level.dat，说明拿错了文件或文件已经损坏。

常见问题

PocketMine-MP 使用与基岩版相同的 level.dat 吗？

是。PocketMine-MP 实现基岩版世界格式，因此其 level.dat 是带 8 字节文件头的小端序 NBT，与 Vanilla 基岩版服务器写入的结构逐字节相同。

为什么控制台中的两个世界名称相同？

因为两者从同一文件夹复制而来，共用同一个 LevelName。文件夹名称与标签相互独立；请修改该标签。

无需重启服务器就能重命名世界吗？

不能。世界加载在内存中并会在保存时重写，因此服务器运行期间的编辑会被丢弃。请停止服务器、编辑，再启动。

支持 Nukkit 和 PowerNukkitX 吗？

支持。它们使用相同格式、相同文件路径和相同操作步骤。

如何将基岩版世界转换为 Java 版？

NBT 编辑器无法完成这种转换。字节序只是简单部分；标签布局、方块调色板和区块存储完全不同。请使用专用转换器，再用本编辑器处理剩余元数据。
