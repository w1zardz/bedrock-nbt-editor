8 字节文件头及其作用

基岩版 level.dat 不是原始 NBT。前 4 个字节是小端序存储版本（实际常见值为 8 和 10），接下来的 4 个字节是 NBT 负载的字节长度，之后才是未压缩标签。如果编辑负载后未修正长度，游戏就会拒绝文件；使用仅支持 Java 的 NBT 工具打开基岩版存档时通常会出现此问题。

偏移量大小字段
04 字节存储版本，小端序 int
44 字节负载字节长度，小端序无符号整数
8其余部分小端序 NBT、根复合标签、未压缩

本编辑器会在文件栏显示存储版本，保留该值，并在每次保存时自动重写长度。

常用的基岩版标签

基岩版将设置平铺在 level.dat 根节点，而不是像 Java 那样嵌套在 Data 复合标签下；游戏规则也是独立标签，而不是 GameRules 子项。

标签类型含义
LevelNameString世界列表和服务器输出中显示的世界名称
GameTypeInt0 生存、1 创造、2 冒险
DifficultyInt0 和平…3 困难
commandsEnabledByte开启或关闭作弊
SpawnX, SpawnY, SpawnZInt世界出生点
RandomSeedLong世界种子，真正的 64 位值
lastOpenedWithVersionInt 列表最后写入世界的客户端或服务器构建版本
StorageVersionInt世界存储修订版本，与文件头对应
experimentsCompound该世界启用的实验性开关
keepinventory, domobspawning, …Byte游戏规则，每项对应一个小写标签

在各平台查找文件

  • Android：Android/data/com.mojang.minecraftpe/files/games/com.mojang/minecraftWorlds/<id>/level.dat。较新的 Android 版本会限制该文件夹；请使用游戏内世界导出功能，或具有相应访问权限的文件管理器。
  • iOS：在游戏中将世界导出为 .mcworld，用“文件”App 打开并解压；level.dat 位于压缩包根目录。
  • Windows：%LOCALAPPDATA%\Packages\Microsoft.MinecraftUWP_8wekyb3d8bbwe\LocalState\games\com.mojang\minecraftWorlds\<id>\level.dat。
  • Bedrock Dedicated Server：worlds/<World>/level.dat。
  • PocketMine-MP、Nukkit、PowerNukkitX：worlds/<World>/level.dat；请参阅服务端指南。

世界文件夹名称是随机 ID，不是世界名称。可按修改时间排序，或在此打开几个 level.dat 文件并读取 LevelName，以确定正确文件。

level.dat 以外的文件

基岩版将区块、实体和方块实体保存在 db/ 文件夹的 LevelDB 数据库中，许多键的值都是小端序 NBT。提取一个值后，可在此以基岩版原始格式打开，无文件头、无压缩。结构文件使用相同编码，请参阅 .mcstructure 编辑器。协议捕获使用 varint 变体，编辑器会将其识别为基岩版网络格式。

常见问题

为什么基岩版 level.dat 无法在 NBTExplorer 中打开？

因为 NBTExplorer 按 Java 的大端序布局读取，也不了解基岩版的 8 字节文件头。本编辑器支持两者，并会在保存时重写文件头中的长度。

可以在手机上编辑 MCPE 世界吗？

可以。在手机浏览器中打开本页，从文件管理器选择文件，编辑并保存。下载文件会进入“下载”文件夹，再将其复制回原文件位置即可。

存储版本 8 和 10 有什么区别？

它们标记基岩版世界存储格式的不同修订版本；当前客户端写入 10。编辑器会保留文件原有值，而不会强制替换，因为重写该值并不会迁移其后的世界数据。

支持 .mcworld 文件吗？

不能直接打开，因为 .mcworld 是 zip 压缩包。将其解压，在此编辑 level.dat，再放回压缩包并将扩展名改回 .mcworld。

支持基岩版游戏规则吗？

支持。基岩版将每条规则保存为根节点下独立的小写 byte 标签，例如 keepinventory、domobspawning、showcoordinates。将 byte 设为 1 或 0。完整列表见游戏规则指南。
