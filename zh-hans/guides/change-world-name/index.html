如何修改 Minecraft 世界名称

支持 Minecraft 基岩版和 Java 版，也支持两者所有常见或少见的服务端核心：Vanilla、Paper、Spigot、Purpur、Folia、Fabric、Forge、NeoForge、Mohist、Sponge、Bedrock Dedicated Server、PocketMine-MP、Nukkit、PowerNukkitX、Cloudburst、Dragonfly、Endstone、LeviLamina 等。完整列表。

世界的显示名称由 LevelName 标签保存，该标签位于 level.dat 内，而不在文件夹名称中。重命名文件夹不会改变游戏显示的内容，因此复制出的世界仍会使用原来的名称。将 level.dat 拖入下方编辑器，它会直接定位到 LevelName；修改值并保存，再将文件放回原处。

为什么重命名文件夹没有作用

Minecraft 将文件夹视为地址，将 LevelName 视为标签。世界列表、服务器控制台、世界管理插件以及在聊天中输出“world”的功能都会读取此标签。因此复制文件夹（例如 cp -r worlds/hub worlds/hub2）会得到两个都自称为 hub 的世界，只能在文件内部修正。

在服务器上，重名不只是容易混淆。按内部名称解析世界的插件可能会操作错误的世界，例如传送点、按世界划分的配置、保护区域和经济倍率。复制世界后应立即重命名此标签，并在任何组件缓存名称前完成。

各平台的处理方式

Java 单人游戏

客户端可在世界选项界面重命名，并会替你修改 LevelName。当世界无法加载、正在处理副本，或希望文件夹名与显示名有意不同时，才需要手动编辑文件。

Java 服务器

level-name 在 server.properties 中用于选择要加载的文件夹，不会重命名任何内容。要修改显示名称，请编辑 LevelName，它位于 world/level.dat 中。

基岩版和 MCPE

游戏内的世界编辑界面可以重命名世界。当世界位于服务器上，或需要修改导出的 .mcworld 时，请直接编辑 LevelName，它位于 level.dat 中。基岩版将其以未压缩形式平铺保存在根标签中，并带有 8 字节文件头，编辑器会自动处理。

基岩版服务器（PocketMine-MP、Nukkit、BDS）

文件和标签相同，也同样必须先停止服务器。服务器页面提供了完整流程，包括复制文件夹的情况。

名称没有变化时

  • 服务器仍在运行。下次保存时，内存中的旧副本会覆盖已编辑的文件。停止服务器后重新修改。
  • 编辑了错误的世界。基岩版世界文件夹使用随机 id。编辑前先打开文件并读取 LevelName，确认选对了世界。
  • 编辑了 level.dat_old。这是上一次存档，而不是当前使用的文件。
  • 启动器或面板缓存了名称。部分托管面板显示其自身数据库中的名称，而非世界文件中的名称；游戏内显示仍会正确。
  • 世界现在完全无法加载。恢复备份，并参阅修复损坏的 level.dat。

常见问题

重命名世界会删除任何内容吗？

不会。LevelName 只是标签。地形、玩家、物品栏和实体保存在其他文件中，不受影响。

世界名称可以包含空格、颜色或表情符号吗？

可以使用空格。分节符颜色代码在部分服务端软件中有效，在其他软件中会显示为普通字符。编辑器会按版本使用正确的字符串编码，因此表情符号可完整往返，但控制台和日志文件可能无法正确显示。

还必须重命名文件夹吗？

不必，而且通常不应这样做；服务器的 level-name 设置或插件配置可能指向该文件夹路径。每次只改一处。

玩家会立即看到新名称吗？

世界重新加载后会看到。缓存了服务器列表条目的客户端可能需要刷新。
