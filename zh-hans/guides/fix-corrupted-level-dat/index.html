Fix a Corrupted level.dat

Supports Minecraft Bedrock Edition and Java Edition — and every server core for both, popular or obscure: Vanilla, Paper, Spigot, Purpur, Folia, Fabric, Forge, NeoForge, Mohist, Sponge, Bedrock Dedicated Server, PocketMine-MP, Nukkit, PowerNukkitX, Cloudburst, Dragonfly, Endstone, LeviLamina and the rest. Full list.

A world that refuses to load usually has one of four problems: a truncated level.dat from a crash during save, the wrong compression after a hand edit, a broken Bedrock header length, or a tag whose type was changed. Drop the file below — the editor reports exactly where parsing stopped, which narrows it to one of the four in seconds.

Salvaging a world without level.dat

The world's terrain, chests and players do not live in level.dat — they are in region/ (Java) or db/ (Bedrock). If the metadata file is beyond repair, create a fresh world with the same version and settings, then move the chunk data into it and set LevelName, spawn coordinates and game rules on the new file. You lose the metadata, not the builds. Confirm the version first: a Java world carries DataVersion, and the freshly generated file must not be older than the chunks you are importing.

Preventing the next one

  • Stop the server before copying or editing. Most corruption starts as a file copied while it was being written.
  • Snapshot on a schedule, off the machine. A backup on the same disk does not survive the storage failure that caused the problem.
  • Use save-off / save-all around live snapshots so the copy is taken against a quiesced world.
  • Watch disk space. A full disk truncates saves silently, and level.dat is written last.
  • Edit values, not structure. Renaming tags or changing their types is the one edit the game cannot forgive.

Frequently Asked Questions

What is level.dat_old?

The previous save. Minecraft renames the current file to level.dat_old before writing a new one, so it is a one-generation backup that costs nothing to try first.

Can an NBT editor repair a truncated file?

It can tell you exactly where the data stops, but the missing bytes cannot be reconstructed. A partial parse means you need a backup.

Will I lose my builds?

Not from a broken level.dat alone. Chunks live in region/ or db/; a fresh world file with the same version can adopt them.

The server says level.dat is fine but the world is empty.

Then the chunk storage is the problem, not the metadata. Check that region/ or db/ came along with the copy and that the spawn coordinates in level.dat point where you expect.
